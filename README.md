# LC Music Player（LCMP）

LC Music Player（LCMP）は、落ち着いた音楽鑑賞体験を目指すmacOSのネイティブ音楽プレイヤーです。前世紀（Last Century：LC）の楽曲再生装置のように情報を控えめに表示し、グラフィックイコライザーなどの可視化で再生を楽しめるようにします。

## 主な機能

- **ローカル音源の再生**：ファイルやフォルダを登録して再生します。音楽ファイル自体はアプリへコピーしません。対応形式はMP3、M4A（AAC・ALAC）、WAV、AIFF、FLACです。
- **複数のプレイリスト**：リストの作成・改名・削除と、M3U8の読み込み・書き出しができます。ライブラリ・リスト・現在の対象は保存され、次の起動時は自動再生せずに復元します。
- **可視化**：再生中の周波数レベルを、`LCMP_default_GEQ`の16列の蛍光管LEDで−80〜0dBFSの範囲に表示します。ミュート中も音源のレベルに反応します。拡張画面の表示タブで、5匹のオコジョが音域ごとに歌う「MICRIGAIKE コジョーズ」に切り替えられます。
- **曲ごとの音量をそろえる**：全曲のLUFSとtrue peakを測定して、曲ごとに固定のゲインを適用します（既定OFF）。手動音量・ミュートは独立して使えます。
- **背景での事前測定**：プレイリストへの追加時と起動時に、各曲の音量を背景で順次測定し、結果をキャッシュします。事前測定だけでは再生音量を変えません。
- **出力デバイスごとの音量**（予定）：出力デバイスごとにアプリ内の音量を記憶し、再接続時に復元します。現在のアプリ内音量は、アプリの実行中だけ保持します。

仕様と設計の詳細は[文書一覧](docs/README.md)を参照してください。

## ビルドして起動する

macOS 14以降、Swift 6.2以降に対応するXcode／Command Line Tools、Python 3.9以降を使用します。

```sh
make release
open build/release/LCMP.app
```

- 起動中のアプリと同じ出力先を置き換えないでください。終了してから再ビルドするか、`make release RELEASE_OUTPUT=build/preview/LCMP.app`のように別の出力先を指定します。
- 開発用は`make debug`、ローカル検証用のZIPは`make archive`、コーデックをソースから構築し対応ソースと再リンクの材料を含める配布準備用のZIPは`make distribution`です。
- ビルドスクリプトは、公開依存を取得するときのキーチェーン・netrcの検索を無効にします。Gitの設定やキーチェーンは変更しません。

前提環境、出力先の変更、配置・更新、署名と配布の範囲は[ビルド・配置手順](docs/build-and-deploy.md)を参照してください。

## 使い方

| 操作 | 方法 |
| --- | --- |
| 音源を登録する | メニュー→音源タブからファイル／フォルダを登録します。ファイルはCommand＋Oでも登録できます |
| リストに曲を追加する | リストの「曲を追加」から登録します |
| 再生する | 停止・一時停止中は、曲行をダブルクリックするか、単クリックで選んでからメインの再生ボタンを押します。「このリストを再生」で先頭から始めることもできます |
| 曲を切り替える | 再生中は、別の曲行を単クリックすると切り替わります |
| 一時停止・再開 | Spaceキー |
| シーク | 表示領域をクリックするとシークバーが出ます。ドラッグで位置を移動します |
| 音量 | 音量ボタンで縦型の音量を開きます。小音量を細かく調整できます。フォーカスが外れるか15秒間操作がないと閉じます |
| リストを管理する | 管理からリストの作成・改名・削除と、M3U8の読み込み・書き出しを行います |
| 拡張画面を開く | メニューボタンで下部に拡張画面を開きます |

停止後は先頭から再生し、シークで再生位置を準備できます。

## テスト

```sh
make test
LCMP_TEST_AUDIO_OUTPUT=1 ./scripts/swift.sh test --no-parallel
```

- 1つ目は通常のテストで、音声を出力しません。
- 2つ目は、既定の出力先へ小さいテスト音を送る実再生のテストです。短い音源の観測が他のテストに妨げられないよう、`--no-parallel`を明示します。
- ファイル選択画面、聴感、デバイスの切替の手動確認の方法は[基本再生機能の実装設計](docs/design/02_playback-implementation.md)を参照してください。

## 開発の運用

このリポジトリではGitflowを基にブランチを運用します。現在、リモートリポジトリは設定していません。

| ブランチ | 用途 |
| --- | --- |
| `main` | リリースできる履歴とバージョンタグを管理します。通常の開発では直接コミットしません |
| `develop` | 日常の開発内容を統合します |
| `feature/<短い名前>` | `develop`から作成し、作業の完了後に`develop`へ統合します |
| `release/<バージョン>` | リリースの準備時に`develop`から作成します。検証後に`main`へ統合してタグを付け、変更を`develop`にも反映します |
| `hotfix/<短い名前>` | リリース済みのバージョンへの緊急の修正用として`main`から作成し、`main`と`develop`の両方へ統合します |

設計書には合意した仕様と実装済みの設計を記載します。作業の進め方と記録の扱いは[AGENTS.md](AGENTS.md)に定めています。
