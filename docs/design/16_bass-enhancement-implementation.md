# 重低音の強調の実装設計

[設計書一覧](../README.md)に戻る。

## 1. 概要

本書は、ヘッドフォン・イヤフォンで不足しがちな重低音を強める後処理の段を記述する。低域を一律に持ち上げるのではなく、低域の立ち上がり（キック・タムなど）を主に強め、持続する低音（ベースの伸ばした音など）は控えめに強める。

- 設定は「切／弱／強」の3段階とし、macOS版とiPhone版で同じ処理を使う。
- 段の位置と、ほかの段との関係は[音量自動調整の実装設計](06_volume-normalization-implementation.md)の「処理段の重ね合わせと順序」に従う。

## 2. 要件

- 「切」では入力をビット単位でそのまま出力する。
- 音声を遅らせない。先読み・バッファの蓄積をせず、段の報告する遅延は0とする。可視化との時刻のずれは、段がないときと区別できない大きさ（低域の位相による数十µs）にとどめる。
- 段階の変更は再生を止めずに反映し、波形に段差を作らない。
- 強めた分で出力が−1dBFSを超えない。
- 音量自動調整の測定値・補正計画は、この段の設定によらず有効とする。段階の変更で再測定・一時停止をしない。
- 設定は永続化し、既定は「切」とする。

範囲外とするもの：

- 音色によって楽器を見分けることはしない。ベースの鋭い立ち上がり（スラップなど）も、立ち上がりとして強まる。
- 利用者による周波数・量の細かな調整は提供しない。

## 3. 方式

```text
… → レベル自動調整 → 重低音の強調 → mainMixer（手動音量・ミュート）→ 出力
```

- 段は、レベル自動調整の後、手動音量の前に置く。保護の段（後述）がピークを最後に抑えるためである。音量自動調整の補正はこの段より前に決まり、測定はこの段を通らない音声で行う。
- 可視化の観測はこの段より前にあり、解析する音声はこの段の設定に影響されない。

| 担当 | 内容 |
| --- | --- |
| PlayerUI | 設定タブの「重低音を強調」（切／弱／強のセグメント）を表示し、LibraryControllerへ渡す |
| LibraryController | 設定を`bassEnhancement`（0〜2の整数）として保存し、起動時にPlaybackControllerへ渡す |
| PlaybackController | 段階を保持し、現在と以後のバックエンドへ渡す |
| AudioEngineBackend | 再生グラフの段へ段階を設定する。次の曲へ引き継ぐグラフでも同じ段階を設定する |
| AudioProcessingCore | `BassEnhancement`（段階）、`AudioProcessingChain.bassNode`（段のノード）、`BassPunchUnit`（Audio Unit） |
| LevelDSP | `LCMPBassPunch`（信号処理）。レンダースレッドで動き、メモリの確保やロックをしない |

- `BassPunchUnit`はプロセス内に登録した`AUAudioUnit`のサブクラスで、`AVAudioUnitEffect`として同期的に作る。入出力は同じ形式（Float32・非インターリーブ・1〜2チャンネル）で、レンダリングの資源の確保時にレートとチャンネル数から信号処理を作る。
- 登録する記述には`kAudioComponentFlag_SandboxSafe`を付ける。App Sandbox（macOS版と、すべてのiOSアプリ）では、この印のない部品は利用者の同意待ちになって作れず（-3000）、`AVAudioUnitEffect`が例外を投げる。自動テストはSandboxの外で動くので、印の有無を別に検査する。
- 段階は原子的な整数で渡し、レンダースレッドが各ブロックの先頭で読む。

## 4. 実装

### 信号処理

各サンプルで次を行う。

1. 低域の取り出し：各チャンネルを2次のButterworthハイパス30Hz → ローパス130Hzに通す（帯域b）。
2. 立ち上がりの検出：全チャンネルの|b|の最大を、速い包絡（立ち上がり1ms・減衰60ms）で追う。速い包絡を、遅い包絡（立ち上がり50ms・減衰60ms）で追う。遅い包絡に対する速い包絡の比が1dBから9dBのあいだを0〜1に写し、立ち上がり2ms・減衰40msでならしてパンチ量pとする。持続音では速い包絡のうねりが小さく、pはほぼ0になる。
3. 加算：出力 = 全体の減衰 ×（入力 ＋（固定量 ＋ パンチ量 × p）× b）。
4. 保護：全チャンネルの絶対値の最大が−1dBFSを超えるなら、超えないところまで即座に下げ、150msで戻す。先読みはしない。

| 段階 | 固定量 | パンチ量 | 全体の減衰 |
| --- | --- | --- | --- |
| 切 | 0 | 0 | 0dB |
| 弱 | 0.30 | 0.90 | −0.5dB |
| 強 | 0.55 | 1.45 | −1dB |

- 全体の減衰は、中高域が小さく聞こえない程度にとどめる。足りない余裕は保護の段が補うので、音圧の高い曲ではキックのたびに保護が働くことがある。

- 段階を変えると、固定量・パンチ量・全体の減衰を時定数15msで新しい値へ移す（約50msで落ち着く）。「切」へ移るときは保護の段も同じ速さで戻し、新たには下げない。移り終えると入力をそのまま出力する。
- 「切」の間も、フィルターと包絡は動かし続ける。段階を上げた直後から、温まった状態で働く。
- 加算する帯域は2次のフィルターの位相を持つ。低域の合成の位相の遅れは60Hzで0.1ms未満である。130Hzより上では位相の回り込みでわずかに減り、減衰を除いて200〜300Hzで約−0.3〜−0.6dBとなる。

### 特性の目安

48kHzで、全体の減衰を除いた相対値を示す。

| 入力 | 弱 | 強 |
| --- | --- | --- |
| 持続する60Hz | +2.2dB | +3.6dB |
| キック（90→50Hzの掃引、減衰80ms）の先頭40ms | +6.0dB | +8.6dB |
| 1kHz以上 | 0dB | 0dB |

## 5. 検証

### 合格基準

- 「切」は入力とビット単位で一致し、再生グラフでは段がない場合の出力と一致する（1・2チャンネル）。「強」から「切」へ移った後も、落ち着いた後は入力と一致する。
- 持続する60Hzが固定量の分だけ上がり、3kHzは全体の減衰の分だけ下がる。15Hzはほとんど上がらない。
- キックの先頭は持続音より、「弱」で2dB、「強」で3dBを超えて強まる。
- 0.95の振幅のキックと雑音の入力で、出力のピークが−1dBFSを超えない。
- 段階の変更の前後で、隣り合うサンプルの差が「強」の定常状態の差の1.05倍を超えない。
- インパルスが同じフレームに出て、それより前は0である（信号処理単体と再生グラフ）。60Hzの位相の遅れが5ms未満である。段の報告する遅延は0である。
- 段階が次の曲と再生中の曲のバックエンドへ届き、再生を止めない。設定が保存され、次の起動で反映される。不正な保存値では「切」となる。

自動テストは`BassPunchTests`、`BassStageGraphTests`（AudioProcessingCoreTests）、`PlaybackControllerTests`、`BassEnhancementSettingTests`（LibraryCoreTests）にある。音質は実機で聴いて確かめる。
