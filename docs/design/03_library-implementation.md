# ライブラリ・プレイリストの実装設計

[設計書一覧](../README.md)に戻る。

## 1. 概要

本書は、`Sources/LibraryCore`が担当するライブラリとプレイリストを記述する。音源の登録、ファイル参照の保持と修復、保存・復元、M3U8による交換、再生順序と曲の切替を扱う。製品の機能要件は[基本設計](00_basic-design.md)、外観と導線は[UI・UX設計](01_ui-ux-design.md)に記載する。

## 2. 要件

- 音源本体はコピー・移動・削除しない。
- 同じ音源をリストへ複数回登録できる。
- 編集は保存に成功してから画面へ反映する。保存の失敗や破損で既存のデータを失わない。
- 起動時は現在の対象を復元し、自動再生しない。
- 参照できなくなった曲もエントリと順序を残し、修復できるようにする。
- M3U8は信頼できない入力として扱う。

## 3. 方式

`LibraryCore`はライブラリ、プレイリスト、保存・復元、ファイル参照と交換形式を扱う。`PlaybackCore`は現在の1曲を再生し、画面は`LibraryController`を通じて順序と選択を変更する。ファイルアクセスと保存先はプロトコルで差し替えられる。

| 要素 | 担当 |
| --- | --- |
| `LibraryDocument` | schemaVersion、音源、リスト、現在のリストIDとエントリID |
| `LibraryTrack` | 音源ID、表示名、読み取り専用ブックマークと最終URL、登録方法 |
| `MusicPlaylist`／`PlaylistEntry` | リストID・名前、順序付きのエントリIDと音源ID |
| `JSONLibraryStore` | 検証、atomic保存、バックアップ、破損・将来版の保護 |
| `BookmarkFileReferences` | macOSのsecurity-scoped bookmarkの生成・解決・更新 |
| `AudioDiscovery` | 明示選択したファイル・フォルダの列挙 |
| `M3U8` | UTF-8のローカル音源リストの入出力 |
| `LibraryController` | 編集の確定、参照状態、現在曲と順次再生、背景準備の要求 |
| `ShuffleOrder` | ランダム再生の順序（メモリ上だけに持つ） |

- 音源IDとエントリIDを分け、同じ音源をリストへ複数回登録できるようにする。
- 同じファイルの再登録はパスを正規化して既存の音源へまとめる。ファイル内容のハッシュによる同一判定は行わない。
- 表示名はファイル名から拡張子を除いた値、またはM3U8のEXTINFタイトルを使う。埋め込みタグやアートワークは読み取らない。

## 4. 実装

### 保存と復元

保存先はアプリのコンテナ内のApplication Support（`~/Library/Containers/local.lcmp.player/Data/Library/Application Support/LCMP/library.json`）である。パスはFoundationで求め、ハードコードしない。ライブラリ・設定・測定キャッシュはApp Sandboxのコンテナ内だけに置き、コンテナ外の旧保存先からの移行機能は持たない。

- schemaVersionは1で、UUIDと音源参照（元ファイルのパスとブックマーク）をJSONに保存する。
- リスト名が空、IDの重複、存在しない音源・現在エントリへの参照、非ローカルURLは不正データとして拒否する。
- 編集はmain actor上で直列に処理し、保存に成功してから画面の状態へ反映する。
- 直前の正常データを`library.json.backup`へatomic保存した後、新しいJSONをatomicに置換する。
- 読み込み時に本体が壊れていれば正常なバックアップを使用する。次の保存の前に、壊れた本体を`library.json.damaged-<UUID>`へ保全する。
- 復旧できない場合と未対応のschemaVersionでは編集を無効化し、既存データを上書きしない。
- パスとブックマークを含むため、保存先ディレクトリは0700、`library.json`・バックアップ・保全した本体は0600とする。
- 保存直前には最後に読んだ本体と比較し、別の書き手による変更を検出したら保存を拒否する。これは上書き事故の検出であり、複数プロセス間のロックやマージは実装しない。
- 起動時は現在の対象を読み込み待ちの状態へ復元し、自動再生しない。再生位置・再生中フラグ・音量はライブラリへ保存しない。
- 再生関係の設定（最大音量の表示、音量自動調整の有効状態と目標、ランダム再生の有効状態）はUserDefaultsへ保存する。保存先は`PreferenceStoring`として注入でき、テストはメモリ上の実装を使う。UserDefaultsのsuiteは削除しても空のplistが`~/Library/Preferences`に残るため、テストでは作らない。

### ファイルアクセスと修復

ファイル／フォルダの登録は、NSOpenPanelで明示選択した範囲を扱う。

- フォルダの列挙は背景タスクで行い、隠しファイル、パッケージ内部、ディレクトリのシンボリックリンクを走査しない。
- 登録中は編集を無効化し、アクセスできない項目や非対応形式は件数を通知する。
- 拡張子と読み取り可否を登録時に確認し、デコードできるかは再生対象の選択時に確認する。
- 音源ごとに読み取り専用のsecurity-scoped bookmarkを作る。解決時はUI表示とボリュームの自動マウントを要求しない。古いブックマークは更新する。
- security-scoped bookmarkは、ad-hoc署名の再ビルドや再リンクで署名が変わっても解決できる。
- 移動や名前変更への追従はブックマークの解決結果に従い、常に成功するとは限らない。
- 参照できるかどうかは一時状態として、起動時・拡張画面を開くとき・再生選択時に確認する。参照切れでもエントリと順序を残す。

アクセスを保持する期間は次のとおりとする。

| 対象 | 保持する期間 |
| --- | --- |
| 選択したフォルダ | 列挙・登録が終わるまで |
| 再生対象 | 読み込み確認中は一時的に保持し、再生中と一時停止中はPlaybackControllerの`FileLease`1つで保持する |
| 前処理 | 現在曲の測定は再生leaseを共有し、次曲準備は別のlease1つを所有する |

自然終了・停止・失敗時は、エンジン停止後にアクセスを解放し、再開時に再びブックマークを解決して取得する。通常の選択のためだけに、ライブラリ側で同じアクセスを持ち続けない。停止・終了時は前処理のアクセスも取り消し、基盤I/Oと非同期の後処理が終わってから解放する。

エントリの操作は次のとおりとする。

- リスト右端のマイナスは、そのエントリだけを外す。
- 参照切れの行を押すと音源詳細へ進み、同じ音源IDのままファイルを再選択できる。
- ライブラリからの除外は、確認後に全リストの該当エントリも外す。
- 現在のエントリを外す場合は、再生を終了して対象を解除する。
- いずれも元ファイルは残す。

### 再生順序と曲の切替

- 一覧の閲覧と現在の再生リストを区別する。別リストの表示・編集だけでは再生に影響しない。
- 「このリストを再生」は先頭から開始する。
- 曲行は、停止・一時停止中は単クリックで選択し、ダブルクリックで再生する。再生中は別エントリの単クリックで切り替えて再生する。現在行の再クリック・ダブルクリックでは再生を維持する。
- 同じ音源でもentryIDとplaylistIDで行を区別する。
- 前後ボタンは隣のエントリを選び、再生中なら開始、それ以外は待機する。
- 自然終了だけが`onNaturalFinish`を発行し、次の曲へ進む。末尾で止まり、参照切れの次曲を自動で飛ばさない。末尾へのシークは自然終了による次曲送りとして扱わない。
- 登録中の自然終了は登録完了まで保留し、利用者が停止した場合は進めない。

ランダム再生は次のように扱う。

- 有効にすると、現在のリストの全エントリを並べた順序（`ShuffleOrder`）を作る。現在のエントリを先頭に置き、残りをFisher–Yates法（`shuffle(using:)`）で並べる。乱数は`SystemRandomNumberGenerator`を使い、テストでは固定seedの生成器を注入する。
- 1巡で各エントリを1回ずつ再生する。前後ボタンと自然終了はこの順序に従い、末尾で止まる。前へは順序の1つ前へ戻る。
- 「このリストを再生」はランダムに選んだエントリから、曲行の再生操作はそのエントリから、新しい順序を作る。前後ボタンと自然終了では順序を作り直さない。
- 再生中に追加したエントリは、順序のうち現在より後のランダムな位置へ入れる。外したエントリは順序からも除く。リスト内の並べ替えは順序に影響しない。
- 無効にすると順序を破棄し、現在のエントリからリストの順序で進む。
- 有効状態だけを保存し、順序は保存しない。起動後は、最初に必要になった時点で現在のエントリを先頭に作り直す。library.jsonの形式は変えない。
- 次曲の先頭準備と巡回の優先順位は、この順序の直後・直前を対象にする。

対象の切替は、一時的なファイルアクセス・デコーダ・音量の準備、必要な保存、旧音源の停止、新しい対象の公開の順に行う。準備や保存に失敗した場合は、旧再生と選択を維持する。バックエンドの古い終了通知はPlaybackCoreの世代管理で無視する。

### 背景準備の要求

アプリは前処理を有効にしてLibraryControllerを作り、音源の確認と再生開始のデコーダI/Oを背景へ渡す。前処理の動作（先頭PCM、全曲測定の巡回と優先順位、leaseの上限）は[再生前処理の実装設計](04_preprocessing-implementation.md)に記載する。

- `selectEntry`の戻り値trueは、要求を受け付けたことを示す。選択の確定は`isPreparing`がfalseになるまで待つ。
- 確定の前に対象と参照を再確認し、保存に成功してから選択を公開する。
- 停止・別の選択・終了は世代を更新して古い要求を取り消す。
- 利用者の明示的な選択が準備中なら、自然送りはその要求を上書きしない。
- `clickEntry`は、同じエントリ・参照の選択準備中に2回目のクリックを受けると、MainActor上の`SelectionIntent.autoPlay`を更新する。同じ先頭準備の要求は取り消さない。音量自動調整ONでは測定完了後に再生する。
- Stop・設定変更・別の対象への切替では、この意図も取り消す。参照の修復・行の削除があった場合は、確定前の照合で破棄する。
- library.jsonの形式は変えない。正常な読み込み・編集の保存の後に、音源ID集合で[測定キャッシュのAudit](05_measurement-cache-implementation.md)を行う。

### M3U8交換

管理画面で読み込み・書き出しを行う。

読み込みは次のように扱う。

- 新しいリストを作成する。UTF-8（BOM可）、EXTM3U、EXTINFタイトル、相対パス、絶対パス、ローカルfile URLを扱い、曲順と重複を保持する。
- HTTP等のネットワークURL、HLSのEXT-Xタグ、UTF-8でないデータは拒否する。
- 読み込みは16MiB、項目は50,000件を上限とし、超えるファイルは全体をメモリへ読まずに拒否する。
- 記載された音源が存在しない、またはアクセスできない場合は参照切れとして残し、音源側で再選択する。
- 音源やアクセス権を交換先へ移す機能ではない。App SandboxではM3U8を選んでも、記載先の音源へのアクセス権は得られない。ライブラリに登録済みの音源はパスで既存の音源へまとめるので再生できる。

書き出しは次のように扱う。

- 書き出し先のディレクトリ配下は`./`からの相対パス、それ以外はfile URLで出力する。
- 改行を含むファイル名はエンコードしたfile URLとし、タイトルの改行は空白へ置換する。
- 参照切れも最終URLで書き出す。

### 拡張画面のリスト表示

メインと拡張は同じ`PlayerGlassBackground`を使う。

- 行の高さは44ptに固定する。現在曲は緑の文字LEDと幅2pt・高さ22ptのサイドライト（再生中の不透明度0.55）で示す。操作ボタンはソフトフィルとする。空の通知欄は配置しない。
- `RefinedScrollStyle`はNSScrollViewのつまみを3pt幅で描き、ネイティブの操作範囲を維持する。overlay表示を要求するが、スクロールバーを常時表示するOS設定では余白の取り方が異なる場合がある。
- 曲名領域のマウス入力はネイティブのclickCountを使う。キーボード・支援技術の通常の選択はButtonから同じ`clickEntry`へ渡す。
- 行の並べ替え・削除は独立した24×32ptのネイティブNSButtonを使い、成功時に通知する。
- ドラッグでの並べ替えは`PlaylistClickSurface`が受ける。押してから6pt以上動くとクリックを取り消してドラッグにし、以降はスクロール内容の座標で縦の移動量を測る。行の間隔46pt（行44pt＋間隔2pt）で丸めた位置へ、離したときに`moveEntry(_:in:to:)`で1回だけ保存する。ドラッグ中は`trackEvents`のローカルループで追い、LazyVStackが行を作り直しても入力を失わない。周期イベントで端を越えた間の自動スクロールを続け、Escで取り消す。編集できないときと1曲だけのリストではドラッグを受けない。
- `moveEntry(_:in:to:)`の位置は移動前の挿入位置（末尾は件数）で、エントリIDと現在の再生対象を保つ。シャッフル順には影響しない。
- 現在曲の初期表示はネイティブのレイアウト完了後に行い、開くたびのトークンで一度だけ中央寄せする。行の高さと間隔を変更するときは、この位置計算も更新する。通常の状態更新や手動スクロール中に現在曲へ強制的に戻さない。

曲の追加画面は、閲覧中のプレイリストのエントリから音源IDの所属を判定する。

- `PlaylistTrackChoice`で、追加済みの曲名を白の不透明度0.55（未追加は0.85）にし、控えめな緑の「追加済」を添える。チェック状態とは独立させ、重複追加を禁止しない。アクセシビリティ名とツールチップでも状態を伝える。
- フォルダ内の行コンテナとチェックボックス行は利用可能な横幅を使って左揃えにする。曲名の長さや「追加済」の有無によって、チェックボックス・曲名の開始位置を変えない。

省略された曲名・フォルダ名のツールチップは次のように実装する。

- `OverflowTitle`で、同じフォントの自然幅と実際の表示幅を測定する。自然幅が表示幅を0.5ptより大きく超えるときだけ`quickHelp`を有効にし、約350msのホバーで全文を表示する。
- 表示幅の変化で判定を更新し、全文が収まる場合は待機と表示を無効にする。曲の追加画面は追加済み等の案内を次行に残す。
- `QuickTooltip`の背景マーカーはマウスを透過し、表示用NSPanelはnonactivating・ignoresMouseEventsとする。
- 待機は、退出・入力・スクロール・画面の破棄・ウィンドウ変更・アプリの非アクティブ化で取り消し、画面内に位置を収める。
- アプリ内の省略された曲名・フォルダ名だけに適用し、システムの待ち時間設定を変更しない。

### 音源のフォルダ分け

- `LibraryTrack.registration`は任意のfile/folderで、registrationを持たないschemaVersion 1のデータはnilとして読み込む。
- `SourceFolderGroup.groups`で最終URLの親ディレクトリを正規化して使う。folderの音源を含むか、2曲以上の音源を含む親ディレクトリをグループにする。それ以外（同じフォルダの曲がほかにないファイル登録・M3U8・登録方法が不明なデータ）は「デフォルト」にまとめる。
- グループ化は表示だけで決め、registrationを書き換えない。既存のライブラリにもそのまま効き、曲を除外して1曲に戻ると「デフォルト」へ戻る。
- フォルダを再登録すると既存音源の登録方法をfolderへ更新する。ファイルでの再登録でfolderをfileへ戻さない。
- フォルダはパス順、各フォルダ内は元の登録順とする。同名フォルダでもフルパスが違えば別グループとする。
- `DisclosureGroup`で初期状態は閉じ、見出しにフォルダ名・曲数、配下にインデントした音源行を表示する。パス文字列は見出しやツールチップに出さない。
- 折りたたみは表示状態だけで、JSONやプレイリストを変更しない。
- 音源タブの`SourceFolderList`だけが、フォルダのグループの見出しに除外ボタンを出す（曲の追加画面と「デフォルト」には出さない）。確認の後、`excludeTracks(_:)`がグループの全曲を1回の保存でライブラリと全プレイリストから外す。現在の再生対象が含まれる場合は選択を解除する。2曲以上を除外したときは件数を通知する。
- 参照切れも元の場所に残し、ブックマークの更新後は更新した場所で表示する。

### 終了処理

- 終了コマンドはAppDelegateの専用アクションで受け付け、開いているファイル選択・保存シートを取り消し、オーバーレイと待機タイマーを解除する。
- `LibraryController.shutdown`は編集と次曲送りを無効にし、音声エンジンと参照アクセスを解放する。その後、アプリは`terminateNow`で終了する。
- ライブラリは編集時に保存済みのため、終了時の全件保存は行わない。
- 終了要求、アプリ側の受付、再生エンジンの停止とアクセスの解放、選択の解除、終了直前の時刻を、OSLogのsubsystem `local.lcmp.player`／category `shutdown`へ記録する。曲名やファイルパスはログへ含めない。遅延の調査ではConsoleでこのカテゴリを確認し、入力受付前の遅延と後片付けの遅延を分ける。

## 5. 検証

### 合格基準

- 保存失敗・破損・将来版・別の書き手で既存データを失わず、再起動相当の復元で同じ状態に戻る。
- 実ブックマークの改名・削除、重複エントリ、参照の修復が要件どおりに扱われ、元ファイルが変わらない。
- 次曲送りと遅延通知、M3U8の往復、ネイティブ描画と初期スクロールが動作する。
- ランダム再生の順序が全エントリの順列で、各エントリが各位置に偏りなく現れ、前後・自然送り・編集・設定の保存が要件どおりに動く。

### 自動テスト

```sh
./scripts/swift.sh test --filter LibraryTests
./scripts/swift.sh test --filter ReferenceAndStoreTests
./scripts/swift.sh test --filter Shuffle
./scripts/swift.sh test --filter LibraryEditingTests
./scripts/swift.sh test --filter LibraryOrganizationTests
LCMP_TEST_AUDIO_OUTPUT=1 ./scripts/swift.sh test --filter ShufflePlaybackTests
LCMP_UI_SNAPSHOTS="$PWD/build/library-ui-qa" ./scripts/swift.sh test --filter LibraryNativeViewTests
```

### 手動確認

1. 音源タブで複数のファイルとフォルダを登録し、取消で変更されないことを確認する。フォルダ名・曲数、折りたたみ、参照切れの曲からの修復導線を確認する。
2. 管理から作成・改名し、曲の追加、順序変更、マイナスでの個別削除を試す。追加済みの表示が対象リストごとに変わること、重複追加もできることを確認する。
3. 再生中に別リストを閲覧し、拡張を開き直すと現在曲が見えること、手動スクロールが保たれることを確認する。
4. アプリを終了してから起動し、リストと現在の対象だけが復元され、自動再生しないことを確認する。
5. テスト音源の改名・移動・削除やボリュームの切断で参照状態を確認し、音源詳細で再選択・除外を試す。
6. M3U8の読み込み・書き出し、システムのスクロールバー設定と透明度を下げる設定、キーボードと支援技術での操作を確認する。
