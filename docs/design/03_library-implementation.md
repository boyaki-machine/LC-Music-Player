# ライブラリ・プレイリストの実装設計

[設計書一覧](../README.md)に戻る。製品仕様は[基本設計](00_basic-design.md)、外観と導線は[UI・UX設計](01_ui-ux-design.md)を参照する。

## 構成とデータ

`LibraryCore`はライブラリ、プレイリスト、保存・復元、ファイル参照と交換形式を扱う。`PlaybackCore`は現在の1曲を再生し、画面は`LibraryController`を通じて順序と選択を変更する。ファイルアクセスと保存先はプロトコルで差し替えられる。

| 要素 | 責務 |
| --- | --- |
| `LibraryDocument` | schemaVersion、音源、リスト、現在のリストIDとエントリID |
| `LibraryTrack` | 音源ID、表示名、読み取り専用ブックマークと最終URL、登録方法 |
| `MusicPlaylist`／`PlaylistEntry` | リストID・名前、順序付きのエントリIDと音源ID |
| `JSONLibraryStore` | 検証、atomic保存、バックアップ、破損・将来版の保護 |
| `BookmarkFileReferences` | macOSのsecurity-scoped bookmarkの生成・解決・更新 |
| `AudioDiscovery` | 明示選択したファイル・フォルダの列挙 |
| `M3U8` | UTF-8のローカル音源リストの入出力 |
| `LibraryController` | 編集の確定、参照状態、現在曲と順次再生 |

音源IDとエントリIDを分け、同じ音源をリストへ複数回登録できる。同じファイルの再登録はパスを正規化して既存の音源へまとめる。ファイル内容のハッシュによる同一判定は行わない。表示名はファイル名の拡張子を除いた値、またはM3U8のEXTINFタイトルを使い、埋め込みタグやアートワークは読み取らない。

## 保存と復元

保存先はユーザーのApplication Support内`LCMP/library.json`。schemaVersionは1で、UUIDと音源参照をJSONに保存する。音源本体はコピー・移動・削除しない。リスト名が空、IDの重複、存在しない音源・現在エントリへの参照、非ローカルURLは不正データとして拒否する。

編集はmain actor上で直列に処理し、保存に成功してから画面の状態へ反映する。直前の正常データを`library.json.backup`へatomic保存した後、新しいJSONをatomicに置換する。読み込み時に本体が壊れていれば正常なバックアップを使用し、次の保存前に壊れた本体を`library.json.damaged-<UUID>`へ保全する。復旧できない場合と未対応schemaVersionでは編集を無効化し、既存データを上書きしない。

保存直前には最後に読んだ本体と比較し、別の書き手による変更を検出したら保存を拒否する。これは上書き事故の検出であり、複数プロセス間のロックやマージは実装しない。JSONには元ファイルのパスとブックマークが含まれる。

起動時は現在対象を読み込み待ちの状態へ復元し、自動再生しない。再生位置・再生中フラグ・音量はライブラリへ保存しない。参照可否は一時状態として起動時・拡張画面を開くとき・再生選択時に確認する。参照切れでもエントリと順序を残す。

## ファイルアクセスと修復

ファイル／フォルダ登録はNSOpenPanelで明示選択した範囲を扱う。フォルダの列挙は背景タスクで行い、隠しファイル、パッケージ内部、ディレクトリのシンボリックリンクを走査しない。登録中は編集を無効化し、アクセスできない項目や非対応形式は件数を通知する。拡張子と読み取り可否を登録時に確認し、デコード可能かは再生対象の選択時に確認する。

音源ごとに読み取り専用のsecurity-scoped bookmarkを作り、解決時はUI表示とボリュームの自動マウントを要求しない。古いブックマークは更新する。選択フォルダのアクセスは列挙・登録が終わるまで、再生対象のアクセスは読み込み確認中は一時保持、再生中と一時停止中はPlaybackControllerの`FileLease`1つで保持する。自然終了・停止・失敗時にエンジン停止後アクセスを解放し、再開時に再びブックマークを解決して取得する。通常選択のためだけにライブラリ側で同じアクセスを持ち続けない。前処理の全曲測定中は再生leaseを共有し、次曲準備は別lease1つを所有する。停止・終了時にはこれらも取り消し、基盤I/Oと非同期後処理が終了してからアクセスが解放される。移動や名前変更への追従はブックマークの解決結果に従い、常に成功するとは限らない。

リスト右端のマイナスはそのエントリだけを外す。曲名領域のマウス入力はネイティブclickCountを使い、キーボード・支援技術の通常選択はButtonから同じ`clickEntry`へ渡す。行の並べ替え・削除は独立した24×32ptのネイティブNSButtonを使い、成功時に通知する。参照切れ行を押すと音源詳細へ進み、同じ音源IDのままファイルを再選択できる。ライブラリからの除外は確認後に全リストの該当エントリも外す。現在エントリを外す場合は再生を終了して対象を解除する。いずれも元ファイルは残す。

## 再生順序

一覧の閲覧と現在の再生リストを区別する。別リストの表示・編集だけでは再生に影響しない。「このリストを再生」は先頭から開始する。曲行は停止・一時停止中の単クリックで選択し、ダブルクリックで再生する。再生中は別エントリの単クリックで切り替えて再生し、現在行の再クリック・ダブルクリックでは再生を維持する。同じ音源でもentryIDとplaylistIDで行を区別する。

前後ボタンは隣のエントリを選び、再生中なら開始、それ以外は待機する。自然終了だけが`onNaturalFinish`を発行し、次の曲へ進む。末尾で止まり、参照切れの次曲を自動で飛ばさない。登録中の自然終了は登録完了まで保留し、利用者が停止した場合は進めない。末尾へのシークは自然終了による次曲送りとして扱わない。

対象の切替は一時的なファイルアクセス・デコーダ・音量の準備、必要な保存、旧音源の停止、新しい対象の公開の順に行う。準備や保存に失敗した場合は旧再生と選択を維持する。バックエンドの古い終了通知はPlaybackCoreの世代管理で無視する。

## 背景準備と最大音量測定

アプリは`preprocessingEnabled: true, playlistPreprocessingEnabled: true`でLibraryControllerを作り、音源確認と再生開始のデコーダI/Oを背景へ渡す。`selectEntry`の戻り値trueは要求の受理を示し、`isPreparing`がfalseになるまで選択確定を待つ。対象と参照を再確認し、保存成功後に選択を公開する。停止・別の選択・終了は世代を更新して古い要求を取り消す。利用者の明示選択が準備中なら自然送りはその要求を上書きしない。`clickEntry`は同じエントリ・参照の選択準備中に2回目のクリックを受けると、MainActor上の`SelectionIntent.autoPlay`を更新する。同じprefix要求を取り消さず、補正ONでは測定完了後に再生する。Stop・設定変更・別対象への切替では意図も取り消し、参照修復・行削除は確定前の照合で破棄する。

先頭PCMは現在リストの直後1エントリを準備し、全プレイリストの測定巡回と枠を共有する。曲順・参照・対象の変更で破棄する。音量自動調整ONで同じエントリ・参照へ進む場合は、未完了でも次曲Task・先頭PCM・同じleaseを選択要求へ引き継ぎ、有効な測定完了を待つ。それ以外は取消・終了後に通常の背景準備を行い、OFFで全曲測定を待たせない。プレイリストへの追加・正常起動から全域測定を一件ずつ巡回する。明示再生、再生中の現在曲と前後、残りの順に優先する。表示設定がONなら`peakMeasurement`を表示し、`currentTrackPeak`を音声処理向けに公開する。設定はUserDefaultsへ保存する。ピーク等の完了測定値は専用SQLiteへ保存し、先頭PCMは永続化しない。library.jsonの形式は変えず、正常な読込・編集保存後に音源ID集合で[測定キャッシュのAudit](05_measurement-cache-implementation.md)を行う。プレイリストからの削除とlibraryからの除外を区別する。背景測定中の同じ曲は再生要求へ引き継ぎ、異なる曲への割込みは取消後の解放を待つ。次曲測定後の他曲巡回では先頭PCMを解放し、一巡後に戻すことでlease最大2を保つ。Stop・一時停止・末尾終了では巡回も止める。処理の詳細と検証手順は[再生前処理](04_preprocessing-implementation.md)を参照する。

## M3U8交換

管理画面で読み込み・書き出しを行う。読み込みは新しいリストを作成し、UTF-8（BOM可）、EXTM3U、EXTINFタイトル、相対パス、絶対パス、ローカルfile URLを扱う。曲順と重複を保持する。読み込んだ音源が存在しない／アクセスできない場合は参照切れとして残し、音源側で再選択する。

HTTP等のネットワークURL、HLSのEXT-Xタグ、UTF-8でないデータは拒否する。音源やアクセス権を交換先へ移す機能ではない。サンドボックス等でM3U8内の参照先へアクセスできないときも、音源側で明示的に選び直す。

書き出し先のディレクトリ配下は`./`からの相対パス、それ以外はfile URLで出力する。改行を含むファイル名はエンコードされたfile URLとし、タイトルの改行は空白へ置換する。参照切れも最終URLで書き出す。

## ネイティブ画面と検証方法

メインと拡張は同じ`PlayerGlassBackground`を使う。固定44ptの行、緑の文字LED、幅2pt・高さ22ptのサイドライト（再生中の不透明度0.55）、ソフトフィルの操作ボタンを用いる。空の通知欄は配置しない。`RefinedScrollStyle`はNSScrollViewのつまみを3pt幅で描き、ネイティブの操作範囲を維持する。overlay表示を要求するが、スクロールバーを常時表示するOS設定では余白の取り方が異なる場合がある。

曲の追加画面は、閲覧中のプレイリストのエントリから音源IDの所属を判定する。`PlaylistTrackChoice`で追加済みの曲名を白の不透明度0.55（未追加は0.85）にし、控えめな緑の「追加済」を添える。チェック状態とは独立させ、重複追加を禁止しない。アクセシビリティ名とツールチップでも状態を伝える。

プレイリスト・音源一覧・曲の追加画面は`OverflowTitle`で同じフォントの自然幅と実際の表示幅を測定する。自然幅が表示幅を0.5ptより大きく超えるときだけ`quickHelp`を有効にし、約350msのホバーで全文を表示する。表示幅の変化で判定を更新し、全文が収まる場合は待機と表示を無効にする。曲の追加画面は追加済み等の案内を次行に残す。`QuickTooltip`の背景マーカーはマウスを透過し、表示用NSPanelはnonactivating・ignoresMouseEventsとする。待機は退出・入力・スクロール・画面の破棄・ウィンドウ変更・アプリ非アクティブ化で取り消し、画面内に位置を収める。アプリ内の省略された曲名・フォルダ名だけに適用し、システムの待ち時間設定を変更しない。

曲の追加画面も音源一覧と同じフォルダ分け・名前・曲数・初期状態が閉じた折りたたみを使用する。個別登録は「デフォルト」にまとめ、パスは表示しない。フォルダを閉じても選択した曲は保持し、追加操作は閉じたフォルダ内の選択も含める。

フォルダ内の行コンテナとチェックボックス行は利用可能な横幅を使って左揃えにする。曲名の長さや「追加済」の有無によってチェックボックス・曲名の開始位置を変えない。

`LibraryTrack.registration`は任意のfile/folderで、schemaVersion1の旧データはnilとして読み込む。ファイル登録・M3U8・登録方法不明の旧データは「デフォルト」にまとめる。フォルダ登録だけを`SourceFolderList`で最終URLの親ディレクトリを正規化してグループ化する。フォルダを再登録すると既存音源の登録方法をfolderへ更新し、ファイルでの再登録でfolderをfileへ戻さない。フォルダはパス順、各フォルダ内は元の登録順とし、同名フォルダでもフルパスが違えば別グループとする。`DisclosureGroup`で初期状態は閉じ、見出しにフォルダ名・曲数、配下にインデントした音源行を表示する。パス文字列は見出しやツールチップに出さない。折りたたみは表示状態だけで、JSONやプレイリストを変更しない。参照切れも元の場所に残し、ブックマークの更新後は更新した場所で表示する。

現在曲の初期表示はネイティブレイアウト完了後に行い、開くたびのトークンで一度だけ中央寄せする。行の高さと間隔を変更するときは、この位置計算も更新する。通常の状態更新や手動スクロール中に現在曲へ強制的に戻さない。

```sh
./scripts/swift.sh test --filter LibraryTests
./scripts/swift.sh test --filter ReferenceAndStoreTests
LCMP_UI_SNAPSHOTS="$PWD/build/library-ui-qa" ./scripts/swift.sh test --filter LibraryNativeViewTests
python3 scripts/build-app.py
```

自動検証は保存失敗・破損・将来版・別書き手、再起動相当の復元、実ブックマークの改名／削除、重複エントリ、元ファイル不変、次曲と遅延通知、参照修復、M3U8の往復、ネイティブ描画と初期スクロールを対象とする。次の手動確認も行う。

1. 音源タブで複数ファイルとフォルダを登録し、取消で変更されないことを確認する。フォルダ名・曲数、折りたたみ、参照切れ曲からの修復導線を確認する。
2. 管理から作成・改名し、曲の追加、順序変更、マイナスでの個別削除を試す。追加済みの表示が対象リストごとに変わること、重複追加も可能なことを確認する。
3. 再生中に別リストを閲覧し、拡張を開き直すと現在曲が見えること、手動スクロールが保たれることを確認する。
4. アプリ終了後に起動し、リストと現在対象だけが復元され自動再生しないことを確認する。
5. テスト音源の改名／移動／削除・ボリュームの切断で参照状態を確認し、音源詳細で再選択・除外を試す。
6. M3U8の読込／書出し、システムのスクロールバー設定と透明度を下げる設定、キーボードと支援技術での操作を確認する。

## 終了処理

終了コマンドはAppDelegateの専用アクションで受け付け、開いているファイル選択・保存シートを取り消し、オーバーレイと待機タイマーを解除する。LibraryController.shutdownは編集と次曲送りを無効にして音声エンジンと参照アクセスを解放し、アプリはterminateNowで終了する。ライブラリは編集時に保存済みのため、終了時の全件保存は行わない。

終了要求、アプリ側受付、再生エンジン停止とアクセス解放、選択解除、終了直前の時間をOSLogのsubsystem local.lcmp.player / category shutdownへ記録する。曲名やファイルパスはログへ含めない。遅延の調査ではConsoleでこのカテゴリを確認し、入力受付前の遅延と後片付けの遅延を分ける。
