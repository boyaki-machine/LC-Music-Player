# コンパクト画面の実装設計

[設計書一覧](../README.md)に戻る。

## 1. 概要

本書は、`LCMP_default_GEQ`のメイン画面・拡張画面・ライセンスウィンドウのウィンドウ操作、シーク、音量、キーボードと支援技術への対応を記述する。画面の要件は[UI・UX設計](01_ui-ux-design.md)、再生制御は[基本再生の実装設計](02_playback-implementation.md)、拡張画面のリスト表示は[ライブラリ・プレイリストの実装設計](03_library-implementation.md)に記載する。

## 2. 要件

- メイン画面に曲名を常設せず、可視化と6つの操作だけを置く。
- 拡張画面はメインの直下に付随させ、画面の可視領域からはみ出さない。
- 開閉・最小化・ウィンドウの移動で、再生・音源・音量を変えない。
- すべての操作を、マウスに加えてキーボードと支援技術から行える。

## 3. 方式

画面・操作・可視化を`Sources/PlayerUI/Players/LCMP_default_GEQ/`の1つのフォルダ配下へまとめ、可視化は内部の`Visualization/`に置く。`PlayerUI/PlayerView.swift`は、アプリ向けの入口として実装のViewを呼び出す。テストは`Tests/PlayerUITests/Players/LCMP_default_GEQ/`へまとめる。全体の配置と追加の規約は[Player UI・可視化の開発ガイド](10_player-ui-developer-guide.md)に記載する。

| 要素 | 担当 |
| --- | --- |
| `LCMPApp/AppDelegate` | AppKitのアプリメニュー、ウィンドウの生成・開閉・配置、NSOpenPanel |
| `PlayerUI/PlayerView` | アプリ向けの入口。`LCMPDefaultGEQPlayerView`へ依存を渡す |
| `LCMPDefaultGEQPlayerView` | 360×210ptのメイン、144ptの表示領域、6つの44ptの操作、シークと音量 |
| `PlayerPresentation` | シーク・音量・拡張の表示状態、拡張画面で選択中の領域 |
| `ExtensionView` | 現在のリスト、音源、表示、設定と詳細なエラーの表示 |
| `LibraryControls` | 共通のグラス、薄い塗りのボタン、細いスクローラー、現在曲の初期表示、拡張の高さ変更と追加済みの表示 |
| `NativeControls` | 背景マテリアル、表示領域の移動操作、キーボードと支援技術に対応したスライダー |
| `WindowLayout` | 画面の可視領域内に、メインと直下の拡張を配置する計算 |
| `Visualization/PlaybackVisualization` | 実解析の時刻・世代・再生状態とVisualizationKitの接続 |

- 現在のリストと音源の管理は`LibraryController`へ接続し、前後の曲・順次再生・複数リストの編集を扱う。
- 表示領域は実解析を16列の蛍光管LEDへ渡す。時刻・残光・欠落・寿命は[可視化の実装設計](08_visualization-implementation.md)に記載する。
- デコード・測定・キャッシュはViewが所有しない。

## 4. 実装

### メイン画面

- メインはタイトルバーのない透明なAppKitウィンドウで、SwiftUIをNSHostingViewに載せる。メインと拡張の角丸は12ptとする。
- 操作の背景は、暗いNSVisualEffectViewと半透明のチャコールを重ねる。透明度を下げるアクセシビリティの設定では、背景マテリアルを隠してチャコールを不透明にする。
- 三角は常設し、再生中は緑のPLAY、一時停止中は琥珀のPAUSE、それ以外は消灯に近いSTOPを表示する。記号だけを44×44ptの中心へ配置し、状態の文字はその中心の計算から分離して下へ重ねる。操作名は再生／一時停止／再開に追従する。
- 短い入力の反応は220msで消灯する。音量とメニューは、開いている間は点灯する。
- 利用できない前後の曲は無効にし、発光・曲の変更を行わない。
- 表示タブには、可視化デザインごとに、サムネイル（64×48pt）・表示名（1行）・説明（2行まで折り返す）のカードを縦に並べる。カードの全体が押せるボタンで、選んでいるカードは緑の2.5ptの枠と緑の文字で示し、支援技術には選択中として公開する。選択は`UserDefaults`の`visualizationDesign`に保存し、未保存または不明な値なら蛍光管LED（Last Century イコライザー）にする。

### ウィンドウ操作

- 拡張は幅360pt、初期の高さ300pt、間隔2ptでメインの直下へ配置する。開くたびに現在のリストへ戻り、入力フォーカスを拡張へ移す。閉じても再生・音源・音量は維持する。
- メインがある画面の`visibleFrame`を使い、Dock・メニューバーを避ける。直下の空間が足りないときは、メインを必要な分だけ上へ移す。上下を合わせても収まらない画面では、メインを上端へ置いて拡張を縮め、内容をスクロールする。
- 下端の10ptの操作領域に、24×2ptのつまみを描く。`ExtensionResizeHandle`が開始時の高さとスクリーン座標から要求される高さを算出し、AppDelegateが`WindowLayout.resizedExtensionHeight`で、通常は240pt以上・画面の下端までに制限する。メインと拡張の上端・幅は動かさず、一覧の領域を伸縮する。
- つまみにフォーカスがあるときは、上キーで20pt縮小、下キーで20pt拡大でき、支援技術の増減にも対応する。
- 希望の高さはアプリの実行中に保持し、開閉・最小化・復元でも使う。画面の変更で収まらないときは一時的に縮め、小さな画面では240pt未満も許容する。アプリの終了後の高さは保存しない。
- メインの移動と画面構成の変更時に再配置する。通常の拡張の開閉では、十分な空間があるメインを動かさない。
- 表示領域の移動はグローバルなポインター座標を基準とし、6pt以上動いたらドラッグと判定する。ドラッグ後の解放ではシークの表示を切り替えない。シーク・音量・ボタンはこの移動領域へイベントを渡さない。
- Command＋Wでメインを閉じても再生を続け、Dockまたはウィンドウメニューから再表示できる。拡張がアクティブでもCommand＋Wはメインを閉じる。
- Command＋Mでメインと付随する画面を最小化し、復元時は拡張の表示状態を維持する。
- Command＋Qは再生を終了してアクセスを解放する。

### シーク

- シークは表示領域の下端に透明な背景で重ね、ウィンドウを大きくしない。NSSliderの追跡・入力の機能に、2ptのバーと8ptのつまみを描くセルを組み合わせ、時間の表示を添える。操作領域の高さは24ptとする。
- 再生位置は200msごとに現在のバックエンドから読み、別の音源の位置通知を保存しない。
- PlayerPresentationは2秒の取消できる非表示タイマーを持つ。シーク領域へのホバー、スライダーの入力フォーカスの取得・操作で取り消し、退出・フォーカスの喪失・領域外のクリック・メインのキーの喪失・アプリの非アクティブ化で再設定する。閉じる・最小化・終了時にはタイマーも取り消す。
- シークの表示時は入力フォーカスを強制せず、キーボードではTabでスライダーへ移動できる。
- マウス操作中はUIだけで位置をプレビューし、解放時に確定する。音源・再生状態が変わった場合、表示を閉じた場合、Escapeではプレビューを破棄する。確定する対象のURLが変わっていたらシークを送らない。
- 左右キーと支援技術による変更は、その入力で確定する。再生状態ごとの処理は[基本再生の実装設計](02_playback-implementation.md)に記載する。

### 音量

- 音量ポップアップは54×132ptで、表示領域内に収める。縦のスライダーは上が増加、下が減少とする。上下キーは操作位置を全長の5%ずつ変更する。
- 操作位置`x`に対し、下半分は実倍率`v = 4x²(1−x)`、上半分は`v = x`とし、50%で値と一次導関数が連続になる。
- 表示は実倍率の割合を整数の%へ丸める。AXの値の設定は実倍率0〜1を使い、AXの値の説明も表示と同じ割合を示す。AXの増減は、キーと同じ操作位置の増減へ渡す。
- 表示時には逆変換で現在の倍率に対応したつまみの位置を求め、PlaybackCoreの倍率そのものは変更しない。開いたときはスライダーへ入力フォーカスを移す。

閉じる処理は次のように実装する。

- ポップアップと音量ボタンの外のマウス押下はローカルイベントモニターで観測して閉じ、イベントはクリック先へそのまま渡す。音量ボタンは自身の開閉処理へ渡し、外部のクリック処理による再オープンを防ぐ。ポップアップの破棄時にモニターを解除する。
- アプリの非アクティブ化とメインのキーの喪失でも閉じる。
- `VolumeFocusScope`の独立したhostingのsubtreeで、スライダーと内部のミュートのフォーカスをまとめ、外へ移ったら閉じる。
- `PlayerPresentation`は15秒の取消できる非表示のTaskを持ち、開く・音量の変更・ミュートの操作で更新する。スライダーのnative trackingの開始で取り消し、終了後に再設定する。ホバーでは更新せず、非表示時にTaskを取り消す。

ミュートを解除すると直前のアプリ内音量へ戻り、スライダーを変更した場合はミュートを解除する。音源を差し替えても現在の音量とミュートを維持する。

### キーボードと支援技術

| 入力 | 操作 |
| --- | --- |
| Command＋O | 音源の登録 |
| Command＋I | M3U8の読み込み |
| Space | 再生／一時停止／再開 |
| Command＋ピリオド | 停止 |
| Command＋S | シークの表示切替 |
| Command＋U | 音量の表示切替 |
| Command＋E | 拡張の表示切替 |
| Command＋0 | メインを表示 |
| Command＋M／W／Q | 最小化／閉じる／終了 |
| スライダーの矢印キー | 位置・音量の変更 |
| スライダー上のEscape | ポップアップとシークの表示を閉じる |

- 各ボタンに操作名、三角に再生状態、スライダーに名称と現在値を公開する。
- 支援技術からの値の設定と増減も、通常の操作と同じ変更・確定の処理へ送る。
- メインのエラー表示から拡張の音源領域へ進み、理由の確認と再選択を行える。メインにファイル名は常設しない。

### 設定タブ

- Player UIは再生の開始・前後の曲・停止をLibraryControllerへ渡し、停止は準備中にも有効にする。拡張画面は、準備が0.3秒を超えたとき（`showsPreparationNotice`）だけ状態文を表示する。
- 設定タブはScrollView内に、最大音量測定のToggle、説明、測定状態・dBFSまたは無音を表示し、`setMeasuresMaximumVolume(_:)`で変更する。最小の240ptでも説明を折り返し、残りはスクロールで読める構成にする。
- 音量自動調整のToggleと目標LUFSのPickerも置き、`setNormalizesVolume`／`setNormalizationTarget`へ操作を渡す。`levelMeasurement`に基づくLUFS/true peak、`playback.normalizationPlan`の補正dBと制限の理由を表示し、`preparationStage`で全曲測定中を案内する。
- 自動調整の設定変更による一時停止と、再生を続ける手動音量の操作を区別する。測定・補正の契約は[音量自動調整の実装設計](06_volume-normalization-implementation.md)に記載する。

### ライセンスウィンドウ

- ExtensionViewの`showAcknowledgements`コールバックを設定のボタンから呼ぶ。AppDelegateは`AcknowledgementsWindowController`を1つ所有し、メイン・拡張のdelegateを情報ウィンドウへ設定しない。
- 760×520ptで開き、最小560×360ptのリサイズと閉じる操作に対応する。情報ウィンドウがkeyのときの⌘Wはそのウィンドウを閉じる。原文のコピー・全選択は、標準の編集メニューとNSTextViewのresponderへ渡す。
- 表示モデルとViewは`Sources/PlayerUI/Acknowledgements/`に置き、再生制御・ライブラリへのコールバックを持たない。対象はLCMP本体（`Contents/Resources/LCMPLicense`）と依存の索引（`ThirdPartyLicenses/index.json`）の各項目で、文書はそれぞれの同梱領域から読む。対象がLCMP本体だけなら一覧を置かず1枚で表示し、依存があるときだけ`HSplitView`で一覧を出す。
- `PlayerGlassBackground`を再利用し、darkAquaの不透明なタイトルバー（`titleVisibility = .visible`、`titlebarAppearsTransparent = false`）・文書の選択欄と暗い一覧を組み合わせる。
- 本文のNSScrollView/NSTextViewは背景を透過し、白85%の文字と低彩度の緑の選択範囲を使う。透明度を下げるOSの設定は、共通の背景の不透明色へ反映される。

## 5. 検証

### 合格基準

- 画面の端・負の座標での配置、拡張の再表示、再生状態・シーク・ミュートの境界が仕様どおりである。
- メインとポップアップのネイティブ描画が崩れない。

### 自動テスト

1. 通常のテストで、配置の計算と状態の境界を確認する。
2. `LCMP_UI_SNAPSHOTS="$PWD/build/ui-qa" ./scripts/swift.sh test --filter NativeViewTests`で、メインとポップアップのネイティブ描画を生成する。

### 手動確認

1. アプリで、ファイルの選択と取消、再生状態とLED、メニューの再表示、ドラッグとクリックの区別を確認する。
2. マウス、矢印キー、支援技術でシークと音量を変更し、表示値、音声、ウィンドウの位置を確認する。ミュートとEscape、閉じる・最小化・復元を試す。
3. 下端を上下へドラッグし、幅・上端・メインの位置が固定されること、画面の下端と最小の高さで止まること、閉じて開き直しても高さを維持することを確認する。つまみの上下キーと支援技術の増減も確認する。
4. 複数の画面と画面の端で付随する位置を確認し、macOSの透明度を下げる設定で文字と操作の視認性を確認する。
