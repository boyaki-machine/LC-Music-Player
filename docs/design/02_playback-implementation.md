# 基本再生機能の実装設計

[設計書一覧](../README.md)に戻る。

## 1. 概要

本書は、`Sources/LCMPApp`と`Sources/PlaybackCore`にある単曲再生機能を記述する。選択された1曲を読み込み、再生・一時停止・停止・シークし、アプリ内の音量とミュートを制御する。製品の機能要件は[基本設計](00_basic-design.md)に記載する。

関連する機能は次の文書に記載する。

- 音源の登録・参照の永続化・再生順序：[ライブラリ・プレイリストの実装設計](03_library-implementation.md)
- 先頭PCMの背景準備と全曲測定：[再生前処理の実装設計](04_preprocessing-implementation.md)
- 固定ゲイン段と再生前の検査：[音量自動調整の実装設計](06_volume-normalization-implementation.md)
- 再生PCMの観測と解析の時刻：[周波数解析の実装設計](07_analysis-implementation.md)。解析は再生用ファイルを別途開かず、再生経路からデータを取得する。

## 2. 要件

### 対応音源

| ファイル | 対応内容 |
| --- | --- |
| MP3（.mp3） | MP3音源 |
| M4A（.m4a） | DRMのないAAC／ALAC音源 |
| WAV（.wav） | PCM音源 |
| AIFF（.aif / .aiff） | PCM音源 |
| FLAC（.flac） | 可逆圧縮音源 |

- WAV・FLACの24bit／96kHz入力を扱う。出力条件はOSと出力機器に依存し、入力と同じサンプルレート・ビット深度の出力は保証しない。
- 拡張子の対応判定に加え、通常ファイルで読み取り可能なことと、デコーダで読み込めることを確認する。同じ拡張子の破損ファイルも読み込み失敗として扱う。

### 動作の要件

- 選択された音源を複製・移動しない。
- ファイルを選択しただけでは自動再生しない。
- 選択の失敗や取消で、現在の音源と再生を失わない。
- OSのシステム音量やデバイスのサンプルレートを変更しない。

## 3. 方式

対象はmacOS 14以降である。画面はSwiftUI、ファイル選択はNSOpenPanel、再生はSFBAudioEngine 0.14.0を使用する。依存バージョンは`Package.resolved`で固定する。

| 構成要素 | 担当 |
| --- | --- |
| `Sources/LCMPApp` | ウィンドウ管理、アプリメニュー、ファイル選択 |
| `Sources/PlayerUI` | コンパクト画面、付随する拡張画面、シークと縦型音量の表示 |
| `PlaybackController` | 選択と再生状態、操作、音量、エラーの管理 |
| `LocalFileAccess`／`FileLease` | 通常ファイルの読み取り確認と、security-scoped accessの保持・解放 |
| `PlaybackBackend` | 再生ライブラリに依存しない操作と通知のインターフェース |
| `SFBAudioBackend` | SFBAudioEngineによる再生、アプリ内音量、delegate通知の受け渡し |
| `PreprocessingCore.AudioDecoderFactory` | 拡張子に固定したPCMデコーダの生成・読み込みと、短い音源の互換処理 |

- UIは再生ライブラリを直接操作しない。`PlaybackController`が`PlaybackBackend`を通じて再生を制御する。
- OS依存のファイルアクセスもUIと再生制御から分離する。PlaybackCore自体は保存先やプレイリスト形式へ依存しない。
- UIに渡す状態とイベントはmain actorで処理する。SFBAudioEngineのdelegateからは、デコーダオブジェクトを渡さず、終了・失敗・出力変更のイベントを受け渡す。

## 4. 実装

### ファイルアクセスと選択

- 再生制御は、選択された1曲の元URLを受け取る。NSOpenPanelによる登録と参照の永続化はライブラリ管理が担当する。
- 選択時の読み込み確認は一時的な`FileLease`で保護し、確認完了時に解放する。
- 再生開始時にアクセスを取得し、再生・一時停止中だけ保持する。停止・自然終了・再生失敗・出力変更でエンジンを停止した後に解放し、次の再生時に取り直す。
- 停止中のシークは、その操作中だけアクセスを保持する。
- 再生を停止しただけでは選択を解除しない。

ファイル選択はトランザクションとして扱う。新しい音源の読み込みと、呼び出し側の確定処理（ライブラリ保存）に成功してから、元の再生を停止して選択を差し替える。選択取消・選択失敗では、元の音源と再生状態を維持して取消または理由を表示する。

アプリのリスト選択は、[前処理](04_preprocessing-implementation.md)で読み込みを確認してから確定する。

- `selectMetadata`：未再生の選択で、URL・時間・シーク可否などの軽量情報だけを保持する。
- `selectPrepared`：開いたままの先頭PCM付きデコーダを受け取り、`togglePlayPause(using:)`へ同じleaseを渡して再生を開始する。
- 保存に失敗したときは受領候補を閉じ、旧再生を維持する。
- `onActivityChange`は、LibraryCoreが停止・一時停止等に合わせて先行処理を取消・再開するための通知である。

ライブラリのブックマークから得た`FileLease`は、`select(using:)`で読み込み確認へ、`togglePlayPause(using:)`で再生開始へ渡す。再生側が単独で所有し、通常のライブラリ選択では重複して保持しない。背景測定と先行読み込みでは処理中の同じleaseを共有し、取消後のI/O完了時に解放する。

### 再生状態と操作

| 状態 | 意味 |
| --- | --- |
| `empty` | 有効な音源が選択されていない |
| `ready` | 選択音源を読み込み、再生を開始できる |
| `playing` | 再生中 |
| `paused` | 再生位置を保持して一時停止中 |
| `stopped` | 停止中。先頭またはシークで準備した位置から開始する |
| `finished` | 自然終了。再生すると先頭から開始する |
| `failed` | 再生が失敗して停止した。再試行できる |

- 再生ボタンまたはSpaceは、再生中なら一時停止、一時停止中なら同じ位置から再開、それ以外は先頭またはシークで準備した位置から再生する。
- 停止は再生位置を先頭へ戻し、選択音源を保持する。
- 自然終了では`finished`へ遷移し、表示時間を音源の長さに合わせて`onNaturalFinish`を通知する。次のエントリの選択はLibraryCoreが担当する。末尾へのシークはこの通知を発行しない。
- 再生失敗では再生を停止し、理由を表示する。選択音源は保持して再試行を受け付ける。
- 音声出力の設定変更通知では停止し、利用者の再生操作で先頭から再開する。

再生開始ごとにプレイヤーを生成し、デコーダは準備済みのものを一度だけ引き継ぐか、新たに生成する。停止時にその再生世代を無効化し、選択・停止・シーク・再再生をまたいだ古い通知が新しい状態を上書きしないようにする。プレイヤーへ渡したデコーダの所有権は再生ライブラリへ移し、アプリから変更しない。

音量自動調整がONのときは、前処理が確定した測定profileへ`ProfileDecoder`で変換し、そのFloat32 PCMをSFBAudioEngineへ渡す。再生開始・再開時は音源fingerprintと出力profileを再照合し、補正計画のない再生を拒否する。

### シーク

`PlaybackBackend`は`supportsSeeking`と`seek(to:)`を提供する。音源の長さが有効で、デコーダがシークに対応し、再生失敗状態でないときに操作を受け付ける。非有限値は無視し、範囲外は先頭または末尾へ制限する。

| 操作時の状態 | 確定時の動作 |
| --- | --- |
| `ready`／`stopped` | 位置を準備する。自動再生しない |
| `playing` | 確定位置から新しい再生世代を開始する |
| `paused` | 位置を準備し、一時停止を維持する。再開時にその位置から開始する |
| `finished` | 末尾より前へ移動したら`stopped`となり、位置を準備する |
| `empty`／`failed`／シーク非対応 | シークを無効とする |

- 末尾へ確定した場合は再生を終了し、`finished`と音源長の表示に揃える。
- 停止・出力変更・再生失敗では準備位置も先頭へ戻す。
- シーク失敗は、再生失敗と同じ回復可能な停止とする。
- 再生中のシークはデコーダを新しく開き、所有権を移す前にPCMフレームへシークしてからSFBAudioEngineへ渡す。一時停止・未再生では位置だけ保持し、再開時に同じ処理を行う。
- 所有権を移したデコーダは操作せず、古い終了通知や失敗通知は世代IDで無視する。
- シークによる再生成で短い再生の切れ目が生じ得るため、連続したスクラブ再生は提供しない。圧縮形式の位置精度はデコーダのフレーム解像度に従う。

### 音量と音声出力

- 音声はmacOSの既定出力先へ送る。
- アプリ内音量はmain mixerの`outputVolume`で0〜1に調整する。初期値は0.25である。非有限値は受け付けず、範囲外の値は0〜1へ制限する。
- ミュート中は再生音量を0とし、解除時はミュート前の値を復元する。スライダーを変更するとミュートを解除する。音源選択は音量とミュート状態を維持する。
- 単曲再生の音量値はアプリの実行中に保持し、永続化しない。

手動音量はPlaybackCoreが担当する。PlayerUIが操作を受け、`PlaybackController.setVolume`／`toggleMute`が値と状態を管理し、SFBAudioBackendが`mainMixerNode.outputVolume`へ反映する。音量・ミュートの変更は再生を続けたまま行う。PlayerUIは音量バーの操作位置を小音量側の曲線から実倍率へ変換してこのAPIへ渡し、再生層は非線形の操作位置を保持しない。

自動補正の固定ゲインはmainMixerより前の専用段で適用し、手動音量とは別の倍率として管理する。詳細は[音量自動調整の実装設計](06_volume-normalization-implementation.md)に記載する。

### デコーダの選択と読み込みの互換処理

`AudioDecoderFactory`は拡張子ごとに1つのデコーダ名を指定して、SFBAudioEngineのデコーダを生成・openする。SFBAudioEngineの既定の内容判定は使わない。内容判定では拡張子と無関係に、同梱する全デコーダ（Monkey's Audio、TTA、モジュール形式等）の解析処理へ到達し得るためである。

| 拡張子 | デコーダ |
| --- | --- |
| mp3 | mpg123（`.MPEG`） |
| flac | libFLAC（`.FLAC`） |
| m4a・wav・aif・aiff | Core Audio（`.coreAudio`） |

- PCMコンテナはOS更新で修正されるCore Audioで読み、libsndfileは使用しない。
- 内容が拡張子と一致しないファイルは、指定したデコーダで読めなければ読み込み失敗として扱い、別の解析処理へ回さない。

Core Audioでの読み込みが、下位の`NSOSStatusErrorDomain`のeofErr（-39）で失敗した場合に限り、AVAudioFileでPCMを読み取る`PCMDecoding`アダプターへ切り替える。SFBAudioEngine 0.14.0では、短いM4A・WAV・AIFFでこの失敗が生じる。

- アダプターは、m4aではAAC／ALAC、wav・aif・aiffではリニアPCMであることを確認する。それ以外の形式や読み込み失敗を正常扱いしない。
- PCMの再生は引き続きSFBAudioEngineが担当する。
- 依存ライブラリのソースは変更せず、互換処理をアプリ側のデコーダ生成に集約する。

### エラーの扱い

| エラー | 表示・制御 |
| --- | --- |
| `unsupportedFormat` | 対応形式を案内し、不正な再生要求を送らない |
| `inaccessibleFile` | ファイルの場所とアクセス権の確認を案内する |
| `loadingFailed` | 読み込みの失敗理由を表示する |
| `playbackFailed` | 再生を停止し、理由と再試行可能な状態を示す |

選択段階のエラーでは既存の再生を維持する。再生段階のエラーでは、同期・非同期のどちらも再生制御へ通知して停止する。

## 5. 検証

### 合格基準

- 状態遷移、失敗・取消、遅延通知、アクセスの解放、元ファイルの不変が上の表のとおりである。
- 対応形式のデコード・再生終了、一時停止・再開・停止・再再生、シーク、ミュートの復元が動作する。
- 拡張子に固定したデコーダのPCMが、SFBAudioEngineの内容判定で選ばれるデコーダのPCMと一致する。
- システム音量が変わらない。比較はデバイスから読み取れる場合に行い、比較の可否をログへ出力する。

### 自動テスト

```sh
./scripts/swift.sh test
LCMP_TEST_AUDIO_OUTPUT=1 ./scripts/swift.sh test
```

通常のテストは音声を出力しない。2つ目の出力テストは既定出力先へ小さい正弦波を送る。

テスト音源は独自の正弦波である。開発ビルド後に`python3 scripts/generate-fixtures.py Tests/PlaybackCoreTests/Fixtures`で再生成できる。手動確認用の音源は`python3 scripts/generate-fixtures.py build/manual-audio --duration 12`で生成する。

### 手動確認

1. `make release`でアプリを作成し、`open build/release/LCMP.app`で起動する。
2. 音源タブまたはCommand＋Oから対応音源を登録し、リストの「曲を追加」で追加する。曲行を選んで読み込み待ちを確認する。
3. 再生、Spaceによる一時停止・再開、停止、自然終了後の再再生を試し、音声と再生位置を確認する。
4. 再生中にファイル選択画面をキャンセルし、現在の再生が維持されることを確認する。
5. `broken.wav`を登録してリストへ追加する。再生中にその行を単クリックし、失敗理由が表示され、元の再生が維持されることを確認する。
6. 再生中に別の有効な曲行を単クリックし、その曲へ切り替わって再生が続くことを確認する。
7. 音量操作がアプリ内音量にだけ作用することを確認する。複数の出力先がある場合は、切替・切断時の停止・通知・再試行も確認する。
8. 実際の可聴性・音質を聴感で確認する。
