# 音量自動調整の実装設計

[設計書一覧](../README.md)に戻る。

## 1. 概要

本書は、全曲のラウドネスとピークを併用して曲間の音量差を減らす音量自動調整を記述する。前処理で曲全体を測定し、再生経路で曲ごとに固定のゲインを適用する。

- 実装済み：LUFS・true peakの測定、固定ゲインの適用、測定完了までの再生待ち、設定。
- 将来の機能：EQと同期用ディレイ。処理段の構成と順序だけを定め、現在の実装と区別する。
- 重低音の強調の段は実装済みで、[重低音の強調の実装設計](16_bass-enhancement-implementation.md)に記載する。

前処理のnative先頭PCMとsample peak専用のAPIは[再生前処理](04_preprocessing-implementation.md)に、測定値の保存は[永続キャッシュ](05_measurement-cache-implementation.md)に記載する。

## 2. 要件

### 調整方針

- 曲全体のIntegrated Loudness（LUFS）を用いて、曲間の聴感上の音量差を減らす。
- true peakによって増幅の余裕を判断し、ピークの制約を音量目標より優先する。
- 1曲を通じて同じ倍率を全チャンネルへ適用し、曲内の強弱と左右バランスを保つ。
- 手動音量とミュートを自動補正から分離し、OSのシステム音量を操作しない。
- 測定は背景処理で行い、再生のrender callbackへ全曲の解析・I/Oを追加しない。

範囲外とするもの：

- ピーク制約や増幅上限によって、目標LUFSに達しない曲がある。目標達成のためにピークをつぶすコンプレッサーやリミッターは、この固定ゲイン方式に含めない。
- アルバム内の曲間差を保つアルバム単位の補正、周波数EQ、同期用の音声ディレイは別の機能とする。
- LUFSは聴感に近い指標であり、あらゆる曲・聴取環境の音量感を完全に一致させる保証ではない。dBTPの上限は測定したデジタル音声に対する予測であり、ヘッドフォン等からの物理音圧の上限ではない。

### 設定と画面

- 利用者向けの主設定は「曲ごとの音量をそろえる」とし、既定OFFで永続化する。最大音量の表示設定（`measureMaximumVolume`）とは独立させ、その設定がONでも自動調整をONにしない。
- 自動調整ONはLUFS・ピークの測定を必須とし、最大音量の表示がOFFでも測定する。両方OFFでもプレイリストの事前測定は行うが、未測定であることをOFFの再生開始の条件にしない。
- 目標音量は−23／−18／−16LUFSから選べる。true-peak上限・余裕・増幅上限は設定型で検証し、UIには個別の調整欄を並べない。
- 拡張画面には、測定中、適用中の補正dB、ピーク・増幅上限による制限、補正の対象外、失敗と再試行を表示する。設定を変更しても再生は止めず、新しい補正の準備ができた位置から続ける（[再生準備と操作](#再生準備と操作)）。
- LUFS/dBTP/dBFSを混同した「最大音量」の1値にまとめず、詳細で単位を示す。
- メイン画面に曲名や測定値を常設せず、240ptの拡張画面でも折り返し・スクロールで読める構成にする。

## 3. 方式

### データの流れ

次は、EQと同期用ディレイを無効にし、レベル自動調整を使う場合の構成である。

```text
LibraryCore（再生要求、参照、設定、測定待ち、取消）
    ↓
PreprocessingCore
    ├─ native先頭PCMと再生用デコーダの準備
    └─ 独立デコーダ → 共通の形式変換 → 出力形式に合わせたPCM
                         ├─ sample peak / true peak
                         └─ K-weighting → 全曲LUFS
    ↓ TrackAudioMetrics（完了値＋音源・測定条件の識別情報）
AudioProcessingCore（設定の検証 → NormalizationPlan）
    ↓
PlaybackCore / AudioEngineBackend
    ProfileDecoder → PCMFeeder → playerNode → mixer → 観測ノード → 自動補正gain → 重低音 → mainMixer → OS出力
                              ↓                         手動音量・mute
                         AnalysisCore → 可視化
```

- `AudioProcessingCore`は、数値設定・測定器・補正量の計算・専用のgainノードを持つ。Foundation、AVFAudioと、独立したCターゲット`LevelDSP`を使用し、PreprocessingCore、PlaybackCore、LibraryCore、UIへ依存しない。
- `LevelDSP`はworker上でK-weightingと補間を行い、数値ループを最適化してビルドする。PreprocessingCoreはこのDSPをチャンク入力で利用し、ファイル・デコーダ・測定資源の寿命を管理する。
- PlaybackCoreとLibraryCoreもAudioProcessingCoreの値型を利用する。UIからAudio Unitを直接操作しない。
- 観測用の0band EQはglobalGain=0のままとし、補正専用の0band `AVAudioUnitEQ`をその後へ置く。解析の購読の有無・最小化・ウィンドウの非表示で補正を解除しない。
- 可視化の値は、自動補正・手動音量より前の音源レベルを表し、出力レベル計として扱わない。
- 再生グラフは再生開始ごとに作り、プレイヤーノードとmainMixerの間に形式変換mixer・観測ノード・gain段を置く。プレイヤーノードの入力はデコーダ（またはProfileDecoder）のprocessingFormatとする。

### 処理段の重ね合わせと順序

音声処理部（後処理部）は、フィルターのように複数の機能を順に通す処理列とする。各段を独立して有効・無効にでき、EQだけ、レベル調整だけ、両方とディレイの併用を可能にする。ここでの多重適用は、前段の出力を次段の入力へ渡す直列処理を意味する。

EQと同期用ディレイを含む順序は次で固定する。利用者による並べ替えは提供しない。

```text
形式変換後のPCM
    ├─ 観測 → 周波数解析・可視化
    └─ EQ → レベル自動調整 → 重低音の強調 → 同期用ディレイ → 手動音量・ミュート → 出力
```

| 処理段 | 役割 | 無効時 |
| --- | --- | --- |
| EQ（将来） | 周波数ごとの特性を調整する | 波形をそのまま次段へ渡す |
| レベル自動調整 | EQ適用後の全曲LUFS/true peakを基準に固定ゲインを適用する | gain=0dBで通す |
| 重低音の強調 | 低域の立ち上がりを強め、−1dBFSを超えないように保護する | 波形をそのまま次段へ渡す |
| 同期用ディレイ（将来） | 音声と可視化の同期のために提示時刻を遅らせる。振幅・周波数特性は変えない | 追加遅延0で通す |

- 各段は自身の設定だけを適用し、他の段を暗黙に無効化しない。
- すべて無効なら、後処理部は波形と提示時刻を意図的に変更せず、手動音量段へ渡す。パススルーは後処理部の加工に関する契約であり、手動音量・ミュートやデコード・出力形式の変換も無効になる意味ではない。
- EQを先に置くことで、その増幅・減衰を含む音声に対してレベル調整を決定する。EQが有効なときは測定側でも同じ設定のEQを通し、設定と実装版をMeasurementProfileへ含める。EQのON/OFF・設定変更では以前の測定結果と補正計画を失効させ、レベル調整ONなら再測定してから再生する。EQの音声側と測定側は別のインスタンスとし、フィルターの状態を共有しない。
- 重低音の強調は、保護の段にピークを最後に抑えさせるため、レベル自動調整の後に置く。測定はこの段を通らない音声で行い、段階の変更では測定結果と補正計画を失効させず、再生を止めない。強めた分のピークは、段の中の全体の減衰と保護で抑える。
- 同期用ディレイは波形の振幅を変えない時間移動なので、その遅延量だけの変更では全曲のLUFS/true peakを取り直さない。提示時刻・解析世代・末尾の排出と再生位置の扱いは、[同期補償の契約](07_analysis-implementation.md)に従って更新する。

### 手動音量とミュートの担当

手動音量とミュートは、PlaybackCoreによる再生・出力制御の担当とし、後処理列の後に適用する。

| 担当 | 内容 |
| --- | --- |
| PlayerUI | 音量スライダー・ミュートの操作を受け付け、PlaybackControllerへ渡す |
| PlaybackController | `setVolume`／`toggleMute`で、音量値、ミュート状態、解除時に戻す値を管理する |
| AudioEngineBackend | 最終段の`mainMixerNode.outputVolume`へ音量を適用する |
| AudioProcessingCore | 曲ごとの補正計画と加工段を担当し、手動音量の値を所有・上書きしない |

- 自動補正は曲ごとの差を補う倍率、手動音量は利用者が聴く大きさを決める最終倍率である。全体の振幅には両方の倍率がかかる。
- 手動音量は0〜1の範囲で、1は自動補正後の振幅を維持し、0は無音にする。ミュートはこの最終倍率を0にする。
- 手動音量やミュートは、測定profileと補正計画の入力に含めない。変更しても全曲の再測定・自動ゲインの再計算を行わず、再生を一時停止しない。
- 自動調整のON/OFF・曲の切替でも、手動音量とミュートの状態を維持する。

### 測定結果と再利用の単位

| 型 | 主な内容 |
| --- | --- |
| `MeasurementProfile` | 出力レート、チャンネル配置、mono/stereo変換、変換品質・アルゴリズムの版、測定DSPの版。前段EQの有効状態・設定・実装版はEQ追加時の拡張 |
| `AudioLevelMetrics` | Integrated LUFSまたは測定不能の理由、sample peak、true peak、フレーム数、gating block数 |
| `TrackAudioMetrics` | SourceFingerprint、MeasurementProfile、AudioLevelMetrics、測定完了の識別情報 |
| `NormalizationSettings` | 目標LUFS、true-peak上限、測定誤差用の余裕、増幅上限。有効状態はLibraryControllerが管理する |
| `NormalizationPlan` | 測定profile、設定のsnapshot、適用するgainのdB・線形倍率、制約の理由。音源の照合情報はAudioEngineBackendがTrackAudioMetricsとして保持する |

- `AudioLevelMetrics.loudness`（`IntegratedLoudness`）は、有限の測定値と、無音・gatingの対象なし・短すぎる音源を区別する。JSONやUIへNaN/Infinityを数値として保存・表示しない。ピークの線形0は無音として扱う。非有限の入力サンプルは無音へ置換せず、測定失敗とする。
- `TrackPeak`・`measure`・`currentTrackPeak`はsample peak専用のAPIであり、LUFS/true peak付きの結果と見なさない。全曲のAPIは`measureLevels`、公開状態は`levelMeasurement`、有効な完了値を返す入口は`currentTrackMetrics`とする。
- 測定値は設定の目標LUFSに依存させない。目標や増幅上限だけが変わった場合は、同じ測定結果から計画を再計算する。
- 音源の識別情報・サイズ・更新日時、レート、チャンネル変換、測定版、前段EQが変わった場合は再測定する。URLだけ、曲IDだけ、古いsample peakだけで再利用しない。属性の照合は制御側で行い、render callbackでファイルを調べない。
- 先頭PCMの対象は現在曲と直後の1曲に限り、全曲測定は全プレイリストの所属曲を1件ずつ巡回する。リストに含まれないライブラリの音源は走査しない。
- Stopや終了で進行中の測定とメモリ上の保持を破棄する。同じ有効な計画による一時停止・再開・シークでは全曲の再測定を不要にする。結果の保持にファイルleaseを持たせない。

## 4. 実装

### 測定するPCMの位置

自動補正前・手動音量前の音声を測る。native PCMのsample peakは保持できるが、補正計画には、再生時の形式変換後、かつ前段EQの適用後に相当するPCMから求めたLUFSとtrue peakを使う。EQが無効なら同じ位置をパススルーとする。可視化の周波数解析はEQより前を観測し、この補正用の測定とは分ける。

- monoを同振幅の左右へ複製すると、左右のエネルギー和はmonoと異なる。レート変換もピークを変え得るため、ファイルのnative LUFS/peakだけを出力形式の測定値として扱わない。
- `ProfileConversion`でAVAudioConverterの設定を共有し、測定と、自動調整ONの再生用`ProfileDecoder`に適用する。monoからstereoへは両チャンネルへ同振幅で写す。
- ProfileDecoderはnative先頭PCM付きデコーダを包み、`PCMFeeder`の供給キューで変換後のPCMを返す。その後のmixerへ同じレート・チャンネル数を渡すことで、暗黙のチャンネル変換への依存を避ける。自動調整OFFの再生はnativeデコーダの経路を使う。
- profileへ変換の版を含め、offlineの測定PCMと再生側の波形を照合する。
- profileは再生準備時に実際の出力形式から作り、走査の開始時と再生開始の直前に照合する。走査中に出力が変わった場合、古いprofileのまま再生を始めない。変換APIの設定名が同じだけでは同一の波形と見なさず、照合に通らない変換は対応profileへ登録しない。
- 出力形式の読み取りはエンジンの生成で数msかかるため、出力の機器・レート・チャンネル数（`OutputSignature`）が変わるまで結果を保持する。既定の出力を切り替えた直後の数msは、システムがすでに新しい機器を示していても、新しく作ったエンジンが古い機器の形式を返す。読み取ったレートが機器のレートと違うときはその値を保持せず、再生の開始時にエンジンの形式が保持した値と食い違ったときも保持を捨てる。保持した値が誤ったまま残ると、その機器を使う間は毎回の再生開始が失敗する。読み取り・食い違い・準備し直しは、形式（レート・チャンネル数）だけをログ（subsystem `io.github.boyaki-machine.LC-Music-Player`、category `output`）に出す。
- 全リストの巡回は、測定の終わりにprofileが変わっていれば、その曲を失敗として記録せず、そのときの出力形式で巡回をやり直す。
- 対象はmono/stereoの入力とmono/stereoの処理出力、処理出力レート44.1/48/88.2/96/176.4/192kHz（`MeasurementProfile.sampleRates`）とする。それ以外のレートの出力機器では自動調整不可とする。任意の多ch配置を先頭2chだけで代用しない。未対応の配置や未検証の変換profileは自動調整不可として理由を表示する。自動調整OFFでの再生形式の対応は狭めない。

### Integrated Loudness

ITU-R BS.1770-5の測定方式に沿い、チャンネル別のK-weightingとエネルギーの集約を行う。

- 400msの完全なblockを100ms間隔で評価し、絶対gateと相対gateを適用して全曲の値を求める。
- 左右を波形平均して逆相成分を消さない。
- K-weightingの係数は実際の測定レートへ合わせ、48kHz用の係数を他のレートへそのまま流用しない。
- 方式の詳細は[ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I)と[EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf)を基準にする。

二段階のgatingは次のように実装する。

- 最初の走査では、blockごとのチャンネル重み付きエネルギーをFloat64で記録する。曲全体のPCMは保存しない。エネルギー列を再走査して相対gateを適用するため、同じ音源をもう一度全デコードする必要はない。値の変わるヒストグラムで代用しない。
- blockエネルギーはメモリの配列に持つ。1block 8byte、毎秒10blockなら約0.275MiB/時（10分で約48KB）で、上限を64MiBとする。上限では失敗とし、途中までのLUFSを全曲の値として返さない。ディスクへは書かない。
- 以前の版はblockエネルギーを一時ファイルへ書いていた。起動時に、その版が残したファイルを回収する。回収はプロセス間の排他ロックを取得できたファイルだけに限る。
- 相対gateの再走査は配列の先頭から同じ順に足すので、ファイルを使っていたときと値はビット単位で変わらない。
- EOFの不完全なblockはLUFSへ加えないが、その区間もピークの測定には含める。
- 400ms未満ではゼロ埋めによる架空のIntegrated値を作らず、`tooShort`とする。完全なblockがすべてgateの対象外なら`belowGate`とし、静かなノイズを大幅に持ち上げる根拠にしない。

### ピーク

- sample peakは全チャンネルの絶対値の最大を求める。
- true peakはK-weighting前のPCMを補間して求め、チャンネルごとの最大のうちの最大を使う。LUFS計算用のフィルターをtrue-peakの経路へ入れない。
- 補間はフレームごとの32タップの内積で、計算量の大半を占める。1回の入力（最大8192フレーム）を直前の31サンプルに続けて1列に並べ、16フレームの内積を2要素のベクトルで同時に求める。各フレームの和は1フレームずつのときと同じ順序で足し、積と和を分ける（FMAにしない）ので、結果はビット単位で変わらない。左右のK-weightingも2要素のベクトルで同時に計算する。10分の48kHzステレオで、測定のCPU時間は約1.5秒から約0.65秒になった。値が変わらないことは`MeasurementVersionTests`で確かめる。
- true-peakの測定はBS.1770の補間方式とレートごとのフィルターを使う。44.1kHzでは8倍、48kHz・88.2kHzでは4倍、96kHz・176.4kHz・192kHzでは2倍とし、測定用の内部レートを192kHz以上にする。2倍のレートでは、Nyquistに近い信号（0.45fs）の値が約0.07dB低く出るが、EBU Tech 3341の許容差（+0.2/−0.4dB）に収まる。
- K-weightingはBS.1770が48kHzの係数で示す応答を、各レートで双一次変換により設計する。高域通過の分子は規格の係数と同じく正規化しない（1, −2, 1）ため、通過域の利得がレートで変わり（48kHzで+0.043dB、192kHzで+0.011dB）、48kHzに対して全周波数が一様に最大0.032dBずれる。周波数ごとの形の差は0.02dB未満である。どちらもLUFSの基本信号の許容差（±0.1LU）に収まる。
- 測定の計算量（10分のステレオ、Release、変換を含む）は、44.1kHzの音源を48kHzへ約1.0秒、44.1kHzへ約1.3秒（8倍の補間）、88.2kHzへ約1.8秒、176.4kHzへ約2.2秒、192kHzへ約2.9秒。メーターだけなら192kHzは48kHzの約2倍で、44.1kHzとほぼ同じである（補間の倍率が下がるため）。
- Cの32tap Blackman窓付きsinc補間を用い、各位相をDC gain=1へ正規化する。倍率だけで適合とせず、補間係数・ゲイン補償・誤差を試験する。
- チャンクの境界でフィルターの状態を保持し、先頭・EOFのフィルター応答も評価する。EOFの排出サンプルはtrue peakの確認用で、曲の長さやLUFSのblockへ加えない。
- 出力音声自体をこの高レートへ変更するものではない。

### キューと完了条件

- 前処理のutility直列ワーカーを使い、8192入力フレーム以下の処理ごとに取消を確認する。
- 優先順位は、明示された再生要求、再生中の現在曲と前後（直後を優先）、現在リストの残り、他のリストの順とする。実行中の低優先度の測定はチャンクの境界で後へ回し、明示された再生を待たせ続けない。
- 背景の測定は1件ずつ処理し、同じfingerprint/profileの要求は合流する。再生用のデコーダは走査へ流用しない。
- 1回の走査からLUFS・sample peak・true peakを作り、別々の全曲走査を重ねない。sample peak専用の要求は、必要なら軽い専用の経路で扱う。
- EOF、既知のフレーム長との一致、形式変換器と補間器の排出、エネルギー列のgating、fingerprintの再照合をすべて終えてからcompleteとする。途中の結果や不一致は計画の作成に使わない。

### 補正量の決定

| 記号 | 意味 |
| --- | --- |
| `T` | 目標Integrated LUFS |
| `C` | true-peak上限（dBTP） |
| `M` | 測定誤差等に備える余裕（0以上のdB） |
| `U` | 自動増幅の上限（0以上のdB） |
| `L` / `P` | 測定したLUFS / true peak（dBTP） |

これらは別々のパラメーターであり、目標LUFSをピーク値で代用しない。設定値は有限で、`T < 0`、`C <= 0`、`M >= 0`、`0 <= U <= 24`を満たすものだけを受け付ける。増幅の技術的な上限24dBはAUの表現範囲であり、推奨値ではない。さらに検証済みの設定profileに含まれることを確認し、未検証の保存値をそのまま適用しない。不正な値は基準のprofileへ戻す。

```text
ラウドネスから必要な補正 = T − L
ピークから許される補正   = C − M − P
適用補正 G              = min(T − L, C − M − P, U)
線形倍率                 = 10^(G / 20)
```

- 減衰を0dBへ丸めたり、増幅時だけピーク制約を適用したりしない。減衰の下限を設けて必要な補正を妨げない。
- AUの表現範囲を超える補正や非有限の演算結果は、下限へのclampで正常扱いせず、再生準備の失敗とする。
- 無音はgain=0dBとする。`tooShort`または`belowGate`で有限のLUFSが得られない非無音は、増幅せず`min(0, C − M − P)`で必要な減衰だけを行い、「ラウドネス補正対象外」と表示する。ピークまで取得できなかった失敗とは区別する。
- 計画は`targetReached`、`peakLimited`、`boostLimited`、`noIntegratedLoudness`、`silent`の理由を持つ。増幅とピークが同じ値で制約する場合は、ピークを優先して表示する。
- `L + G`は予測値として扱う。固定された絶対gateの影響等により、再測定の結果との完全な一致は約束しない。試験では補正後のPCMを独立に測定する。

基準のprofileは、目標−23LUFS、true-peak上限−1dBTP、余裕0.5dB、最大増幅+6dBとする。

- −23/−1は、参照できるEBU R128の基準を開始点として使うもので、放送全体の規格への準拠を表すものではない。
- +6dBは、過度な持ち上げを避けるための製品上の約2倍の増幅制限で、規格由来の値ではない。
- 目標はUIから−23/−18/−16LUFSを選べる。ピーク制約を優先するため、目標が高いほど必ず音が大きくなるわけではない。
- 目標音量の選択はUserDefaultsの`normalizationTargetLUFS`へ、有効状態は`normalizeVolume`へ保存する。

### 再生準備と操作

| 状況 | 動作 |
| --- | --- |
| 自動調整OFF | gain=0dB。全曲のLUFS測定を再生開始の条件にしない |
| ON、有効な測定結果あり | 計画を確定し、最初の出力サンプルから同じgainを適用する |
| ON、未測定 | 測定と準備を背景で行い、完了するまで対象曲の出力を開始しない |
| ON、次曲が測定済み | 次曲の計画と先頭デコーダを再照合して引き継ぐ |
| ON、次曲の測定が間に合わない | 現在曲の終端後に準備を待つ。未補正の再生や黙った曲飛ばしをしない |
| 測定・参照・保存の失敗 | 新しい選択を確定せず、旧選択・旧再生を維持する。失敗を表示する |
| 準備中のStop・別の再生要求・終了 | 要求の世代を無効化し、走査・一時ファイル・デコーダ・leaseを解放する |
| 一時停止・再開・シーク | 同じ音源・profile・設定の計画を保つ。シーク後も途中の区間だけでLUFSを取り直さない |
| 出力形式・チャンネル配置の変更 | 出力変更の一時停止で位置を保持する。再開の要求で出力profileを照合し、変わっていれば新しいprofileで測定・準備してから同じ位置で再開する |
| 準備中・再生開始時の出力形式の変化 | 失敗で止めず、0.3秒待ってから同じ曲・同じ位置で測定・準備し直す（最大3回）。待つ間は「音声出力の切り替えを待っています…」を示し、別の選択・停止で取り消す。3回とも失敗したら失敗を表示し、次の再生要求で準備し直す |
| 一時停止からの再開時の出力形式の変化 | 再開の可否は、再生中の計画のprofileと出力profileで照合する。全リストの巡回は、エンジンが止まるより先に出力の変化を受けて現在の曲を新しい出力で測り直すことがあり、表示用の測定値は再生中の計画と一致するとは限らない（測り直した値は準備で再利用する）。照合を通っても新しいエンジンの形式が違えば再開は失敗するので、そのまま同じ位置から測定・準備し直して再開する（1回の再生要求で再生される） |

- `isPreparing`と`preparationStage`で、先頭準備・全曲測定の短い状態文を拡張画面へ渡す。状態文は、準備が0.3秒を超えたとき（`showsPreparationNotice`）だけ表示する。PCMのチャンクごとのMainActor通知は追加しない。
- LibraryControllerで再生要求を一元管理し、一時停止からの再開、前後の曲、自然送り、再再生も同じ検査を通す。PlaybackController側でも、ONかつ有効な計画がない再生を拒否し、UI以外の経路で未調整の再生ができる抜け道を作らない。
- 準備の失敗を「音源が存在しない」と誤って登録しない。
- 手動で曲を切り替える準備の間は旧再生を維持する。新しい音源・測定・profile・計画をそろえ、ライブラリの保存に成功してから差し替える。準備中に旧曲が自然終了しても、別の自然送りで明示的な要求を上書きしない。保存に失敗したときに旧曲がすでに終わっている場合は、その終了状態を保持する。
- 設定の変更を、再生中のgain段の段差として適用しない。再生中のON/OFFや補正値の変更では、旧計画（OFFならgain 0dB）のまま再生を続け、背景で新しい計画を準備する（測定済みならキャッシュから）。準備ができたら、その時点の再生位置から新しい再生世代に差し替える。差し替えでは、再生中のシークと同じ短い切れ目と、補正量の変化がある。設定の版と実際に適用している計画を区別し、旧計画のまま「新設定を適用中」と表示しない（準備の間の`normalizationPlan`はnil）。
- 準備の間に一時停止・停止・別の曲の選択・自然終了があれば、差し替えを取り消す。自然終了では通常どおり次の曲へ進む。一時停止中の曲は、再開の要求で新しい計画を準備して同じ位置から再開する。一時停止中・停止中の設定の変更も、次の再生要求で準備する。
- 最終段の手動音量・ミュートの変更は、再測定せず再生を続けたまま反映する。

### 資源・音質・遅延の契約

- 再生用のnative先頭PCMの上限2秒/32MiBを維持する。追加の測定は、8192入力フレーム以下のPCM、形式変換・補間の固定作業領域、400ms窓を構成する固定長の状態、blockエネルギーの小さいI/Oバッファを持つ。曲の長さに比例してPCMや測定の履歴をメモリへ蓄積しない。
- アクセスは、現在曲の1つと、次曲準備・巡回が共有する先行の1つを上限とする。該当する曲の走査は同じleaseを共有する。
- 自動調整ONで同じエントリ・音源参照へ切り替える場合は、未完了の次曲のTaskとleaseを選択要求へ移す。異なる要求では投機的な処理を取り消し、その終了を確認してから候補へ枠を渡す。decoder.openの取消できない区間を含めて、新しい処理を無制限に積まない。Stop・終了後は、非同期I/Oの片付けが完了した時点でアクセスを0にする。
- gainは曲の開始前に確定し、再生中は固定する。gain段（`AVAudioUnitEQ.globalGain`）は値を変えると次のレンダリングから段差で変わり、波形の段差は「プツッ」という音になる。再生中に変わる手動音量・ミュート・スリープタイマーのフェードは、変化を約20msの傾斜にするmainMixerの`outputVolume`で適用する。測定器のK-weightingや補間を音声出力の経路へ挿入しない。
- 固定gain段に意図的な音声FIFOやlook-aheadを加えず、曲末に独自の遅延音声を残さない。追加のDSP遅延はインパルスで測定し、未測定のまま「0遅延」を保証しない。全曲測定による開始待ちとは別の値として評価する。
- true peakはprofileに対する推定である。再サンプリングやシーク直後の変換状態、OS・機器での後段の処理は別に誤差を生み得る。余裕`M`を設け、再生経路との照合が通らないprofileは有効にしない。未知の出力経路でも絶対的なtrue-peak上限を保証するには、最終経路の検証や別のリミッターの設計が必要になる。

### 公開入口

- `AudioPreprocessor.measureLevels`：utilityキューで全曲を測定する。native sample peakも同じ走査で求め、最大音量の表示がONの場合の二重の走査を避ける。
- `ProfileDecoder`：元のデコーダから共有の規則で変換したPCMを返す。8192フレームの固定作業バッファと残量を持ち、部分的な読み取りでも要求バッファを満たし、EOFのときだけ短い読み取りにする。シークは入力側の時刻へ換算し、変換器をresetする。
- `LibraryController.setNormalizesVolume`／`setNormalizationTarget`：設定、現在曲・次曲の測定結果、再生準備を管理する。`levelMeasurement`／`currentTrackMetrics`／`preparationStage`を表示へ渡す。
- `PlaybackController.requireNormalization`：有効なときに計画のない再生・再開を拒否する。再生中の旧gainは変えず（差し替えまで旧計画で鳴らす）、再生中でなければOFFで旧gainを解除する。
- `selectPrepared(...metrics:settings:)`：音源と測定結果を照合し、保存の成功後に現在の再生を差し替える。
- `AudioEngineBackend`：開始・再開時にfingerprintと実際の出力profileを再照合し、ProfileDecoderと独立したgainノードを所有する。`AudioProcessingChain`はレベル段を持ち、EQ・ディレイを追加する位置をその前後に定める。

## 5. 検証

### 合格基準

1. 独自に生成した信号で、K-weighting、絶対・相対gate、mono/stereo/逆相、無音、非有限値、EOFの端数と400ms未満を確認する。合成できるEBU Tech 3341の測定試験は各項目の許容差で照合し、LUFSの基本信号は±0.1LUを基準にする。EBUの全機能を実装していない段階で、EBU Mode準拠を名乗らない。
2. 既知のサンプル間ピーク、先頭・末尾のインパルス、チャンクの境界、対応する全レート（44.1〜192kHz）と24bit入力を検証する。各レートで、1kHzの基本信号が±0.1LU、K-weightingの周波数ごとの応答が48kHzと一致し、fs/4と0.45fsのサンプル間ピークが許容差に収まり、そのレートの測定結果で補正のgainが出力にかかることを確かめる（`LevelTests`、`EngineReuseTests`の`aPlanAtTheDevicesRateSetsTheRenderedLevel`）。true-peakの試験は基準信号ごとの許容差を使い、内部の倍率だけで合格としない。
3. 固定ゲインの計算を独立した期待値と比較し、必要な減衰がある場合もピーク制約を守ることを確認する。quiet/tooShort/belowGateで不要な増幅がないことを確認する。適用後のPCMを独立したメーターで測り、予測値・余裕・誤差を区別する。
4. 測定adapterと再生の変換後PCMのLUFS差・true-peak差を、レート変換あり・なし、mono/stereo、シークの境界で比較する。メーターの誤差と変換の誤差の合計が設定の余裕を超えるprofileは不合格とする。下流のハードウェアの音圧はこの判定に含めない。
5. 指標の一時ファイルの上限・取消・失敗・異常終了後の回収、長い入力のメモリ上限、同一要求の合流、明示された再生の優先を確認する。完了前の結果やfingerprint/profileの不一致を再生へ渡さない。
6. 一時停止・再開・シーク、曲の切替・自然送り・Stop・終了、参照の修復・保存の失敗、古い結果、音量・ミュート、解析の購読解除・非表示を回帰する。出力形式の変化では、機器のレートと違う形式を保持しないこと、再生開始の食い違いで保持を捨てること、測定・再生開始・一時停止からの再開が出力の変化で失敗しても測り直して再生し曲送りもできること、巡回がやり直すことを確かめる（`EngineReuseTests`・`OutputChangeSelectionTests`・`PlaylistPreprocessingTests`）。再生の出力は補正の有無を反映し、可視化は同じ補正前の値を保つ。再生と同じグラフ（`PlaybackGraph`）のオフラインのレンダリングで、再生中の音量の変化が波形の段差にならないことと、補正のgainが最初のサンプルから効くことを確認する。自動補正をOFFにするときは、gainを外す前に一時停止することを確認する。
7. OFFとONの波形の誤差、追加のDSP遅延、開始待ち、全曲測定の速度、CPU・RSS、PCMのdropと資源の解放を比較する。10分の固定補正の再生と、全曲走査を伴う条件を分ける。実出力の全回帰は`--no-parallel`で行う。
8. EQ・同期用ディレイの導入時は、各段の単独・全段の併用・各段のバイパスの組合せで、順序と出力を確認する。EQの設定変更で測定・計画が失効し、手動音量・ミュート・時間移動だけの変更では再測定されないことを検証する。自動補正と手動音量の倍率の積、ミュートの解除、自動補正OFFでも手動音量が保たれることを確認する。純粋なディレイの振幅の保存、解析の時刻、末尾の排出の試験も追加する。

### 負荷比較の実行方法

独自に生成した長さ60秒以上の`tone.wav`と`tone.flac`を、検証専用のディレクトリへ置く。利用者のライブラリへは登録せず、テスト用の参照・設定だけを使う。

```sh
LCMP_NORMALIZATION_PROFILE=1 LCMP_NORMALIZATION_SOAK=1 \
LCMP_PREPROCESS_FIXTURES=<検証用ディレクトリの絶対パス> \
  ./scripts/swift.sh test --disable-automatic-resolution --no-parallel \
  --filter PreprocessingPerformanceTests
```

- `normalization-profile.json`に、ON/OFFの定常区間のCPU・RSSと開始待ちを記録する。
- `normalization-soak.json`に、600秒の補正・全曲測定・FFTと繰り返しの切替での、CPU・RSS・PCM drop・最大lease・停止後の解放を記録する。
- アプリ音量は0とし、物理的な出音・画面提示の検証とは区別する。実行中のtest bundleを、別のSwift build/testで上書きしない。
