# LC Music Player（LCMP）

LC Music Player（LCMP）は、静かで個人的な音楽鑑賞体験を目指すネイティブ音楽プレイヤーです。楽曲情報を控えめに表示し、グラフィックイコライザーなどの可視化によって再生を楽しめるようにします。

macOS上のネイティブアプリとし、iPhone版にも共用できるよう、再生やプレイリストの機能と、画面表示、音声出力、ファイルアクセスなどのOS依存機能を分離する設計です。

## 仕様と設計

製品で目指す仕様は[基本設計書](docs/basic-design.md)に、単曲再生の構造と動作は[基本再生の実装設計](docs/playback-implementation.md)に記載しています。単曲再生にはSwiftUIとSFBAudioEngineを使用し、ローカルファイルの選択・再生・一時停止・停止・シーク・縦型アプリ内音量とミュートを提供します。画面構造と操作は[コンパクト画面の実装設計](docs/compact-ui-implementation.md)、音源管理・複数リスト・JSON保存とM3U8交換は[ライブラリの実装設計](docs/library-implementation.md)を参照してください。

製品の設計方針：

- ローカルの音楽ファイル／フォルダを選択して再生します。音楽ファイル自体はアプリへコピーしません。
- グラフィックイコライザーによる可視化を提供し、別の表示デザインも追加・切替できる構造にします。
- 可視化のための解析と、音声に効果を加える処理を分離します。
- 出力デバイスごとにアプリ内の再生音量を記憶し、再接続時に復元します。初めて使うデバイスでは現在のアプリ内音量を使用します。

単曲再生の対応形式はMP3、M4A（AAC・ALAC）、WAV、AIFF、FLACです。次曲の先頭PCMを背景で準備します。設定の「最大音量を測定」をONにすると全曲のsample peakを測定します。初期状態はOFFで、測定しても再生音量は変更しません。詳細は[再生前処理の実装設計](docs/preprocessing-implementation.md)を参照してください。

設定の「曲ごとの音量をそろえる」は、全曲のLUFSとtrue peakを測定して固定ゲインを適用します。既定OFFで、ON時は未測定の曲の測定を再生前に待ちます。手動音量・ミュートは独立して使えます。補正方式、対応出力形式、設定変更時の一時停止は[音量自動調整](docs/audio-processing-design.md)を参照してください。

再生中の周波数レベルは`LCMP_default_GEQ`の16列蛍光管LEDで、−80〜0dBFSの範囲に表示します。緑・黄・赤のセルを点灯し、消灯には短い残光を添えます。ミュート中も音源のレベルに反応します。表示と時刻処理は[可視化の実装設計](docs/visualization-implementation.md)、実装フォルダとモジュールI/F・追加方法は[Player UI・可視化の開発ガイド](docs/playerUI_developers.md)を参照してください。

## ローカルで起動する

macOS 14以降、Swift 6.2以降に対応するXcode／Command Line Tools、Python 3を使用します。

```sh
python3 scripts/build-app.py
open build/LCMP.app
```

起動中のアプリと同じ出力先を置き換えないでください。終了してから再ビルドするか、`python3 scripts/build-app.py --output build/preview/LCMP.app`のように別の出力先を指定します。

メニューの音源タブからファイル／フォルダを登録します（ファイルはCommand＋Oも使用可能）。リストの「曲を追加」で曲を登録し、曲行を選んでからメインの再生ボタンを押すか、「このリストを再生」で先頭から開始してください。管理からリストの作成・改名・削除とM3U8の読み込み／書き出しを行えます。Spaceで一時停止・再開できます。表示領域のクリックでシーク、ドラッグで移動できます。音量ボタンは縦型音量を開き、メニューは下部の拡張画面を開きます。停止後は先頭から再生し、シークで位置を準備できます。音源自体はコピーせず、ライブラリ・リスト・現在対象はJSONとブックマークで保持します。次の起動時は自動再生せず復元します。

ビルドスクリプトは、公開依存を取得するときのキーチェーン・netrc検索を無効にします。Git設定やキーチェーンは変更しません。起動用アプリには動的frameworkと[依存ライセンス表示](docs/third-party-dependencies.md)を同梱します。

## テスト

```sh
./scripts/swift.sh test
LCMP_TEST_AUDIO_OUTPUT=1 ./scripts/swift.sh test --no-parallel
```

2つ目は既定出力先へ小さいテスト音を送る実再生テストです。短い音源の観測が他のテストの処理に妨げられないよう、全体の実出力検証では`--no-parallel`を明示します。通常のテストは音声を出力しません。ファイル選択画面、聴感、デバイス切替の手動確認方法は[実装設計](docs/playback-implementation.md)を参照してください。

## セッションの引き継ぎ

開発途中の情報は次のローカル専用ファイルに記録します。どちらもGit管理対象外で、存在する環境でのみ参照します。

作業開始時に該当する記録を読み、終了時に日付を付けて追記してください。設計書には合意した製品の仕様と実装設計を記載します。記録の扱いは[`AGENTS.md`](AGENTS.md)に定めています。認証情報などの秘密情報は記録しないでください。

## Gitの運用

このリポジトリではGitflowを基にブランチを運用します。現在、リモートリポジトリは設定していません。

- `main`：リリース可能な履歴とバージョンタグを管理します。
- `develop`：日常の開発内容を統合するブランチです。
- `feature/<短い名前>`：`develop`から作成し、機能の作業完了後に`develop`へ統合します。
- `release/<バージョン>`：リリース準備時に`develop`から作成します。検証後に`main`へ統合してタグを付け、リリースブランチの変更を`develop`にも反映します。
- `hotfix/<短い名前>`：リリース済みバージョンへの緊急修正用として`main`から作成し、修正を`main`と`develop`の両方へ統合します。
- 通常の開発では`main`へ直接コミットしません。

初期状態のバージョンは`v0.0.1`です。公開やリモートでの共同作業を始める際に、プロジェクトの管理者がリモートURLを設定してください。
