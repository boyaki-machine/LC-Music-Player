# 基本再生機能の実装設計

[設計書一覧](./README.md)に戻る。

本書は、`Sources/LCMPApp`と`Sources/PlaybackCore`にある単曲再生機能の構造と動作を記述します。製品で目指す機能構成は[基本設計](./basic-design.md)に記載します。

再生PCMの観測ノード、解析セッションと同期用時刻の契約は[周波数解析の実装設計](./analysis-implementation.md)に記載します。解析は再生用ファイルを別途開かず、再生経路からデータを取得します。

LUFSとtrue peakを併用した固定ゲイン段、測定結果の受領と再生前の検査は[音量自動調整](./audio-processing-design.md)に記載します。EQ・同期用ディレイは将来の追加対象です。

## 1. 構成と責務

対象はmacOS 14以降です。画面はSwiftUI、ファイル選択はNSOpenPanel、再生はSFBAudioEngine 0.14.0を使用します。依存バージョンは`Package.resolved`で固定します。

| 構成要素 | 責務 |
| --- | --- |
| `Sources/LCMPApp` | ウィンドウ管理、アプリメニュー、ファイル選択 |
| `Sources/PlayerUI` | コンパクト画面、付随拡張、シークと縦型音量の表示 |
| `PlaybackController` | 選択と再生状態、操作、音量、エラーの管理 |
| `LocalFileAccess`／`FileLease` | 通常ファイルの読み取り確認とsecurity-scoped accessの保持・解放 |
| `PlaybackBackend` | 再生ライブラリに依存しない操作と通知のインターフェース |
| `SFBAudioBackend` | SFBAudioEngineによる再生、アプリ内音量、delegate通知の受け渡し |
| `PreprocessingCore.AudioDecoderFactory` | PCMデコーダの生成・読み込みとM4A互換処理 |

UIは再生ライブラリを直接操作しません。`PlaybackController`が`PlaybackBackend`を通じて再生を制御します。OS依存のファイルアクセスもUIと再生制御から分離します。

## 2. 対応音源とファイルアクセス

| ファイル | 対応内容 |
| --- | --- |
| MP3（.mp3） | MP3音源 |
| M4A（.m4a） | DRMのないAAC／ALAC音源 |
| WAV（.wav） | PCM音源 |
| AIFF（.aif / .aiff） | PCM音源 |
| FLAC（.flac） | 可逆圧縮音源 |

WAV・FLACの24bit／96kHz入力を扱います。出力条件はOSと出力機器に依存し、入力と同じサンプルレート・ビット深度の出力を保証しません。

拡張子の対応判定に加え、通常ファイルで読み取り可能なことと、デコーダで読み込めることを確認します。同じ拡張子の破損ファイルも読み込み失敗として扱います。

NSOpenPanelによるファイル・フォルダ登録と参照の永続化は[ライブラリ管理](./library-implementation.md)が担当します。再生制御は選択された1曲の元URLを受け取り、複製・移動を行いません。選択時の読み込み確認は一時的な`FileLease`で保護し、確認完了時に解放します。再生開始時にアクセスを取得し、再生・一時停止中だけ保持します。停止・自然終了・再生失敗・出力変更でエンジンを停止した後に解放し、次の再生時に取り直します。停止中のシークはその操作中だけアクセスを保持します。再生を停止しただけでは選択を解除しません。PlaybackCore自体は保存先やプレイリスト形式へ依存しません。

ファイル選択はトランザクションとして扱います。新しい音源の読み込みと、呼び出し側の確定処理（ライブラリ保存）に成功してから、元の再生を停止して選択を差し替えます。選択取消・選択失敗では、元の音源と再生状態を維持して取消または理由を表示します。

アプリの背景選択では、[前処理](./preprocessing-implementation.md)で読み込みを確認してから、`selectMetadata`で軽量情報だけを保持する。再生開始は`selectPrepared`で開いたままの先頭PCM付きデコーダを受け取り、`togglePlayPause(using:)`へ同じleaseを渡す。保存失敗時は受領候補を閉じ、旧再生を維持する。`onActivityChange`はLibraryCoreが停止・一時停止等に合わせて先行処理を取消・再開する通知として使う。

## 3. 再生状態と操作

| 状態 | 意味 |
| --- | --- |
| `empty` | 有効な音源が選択されていない |
| `ready` | 選択音源を読み込み、再生を開始できる |
| `playing` | 再生中 |
| `paused` | 再生位置を保持して一時停止中 |
| `stopped` | 停止中。先頭またはシークで準備した位置から開始する |
| `finished` | 自然終了。再生すると先頭から開始する |
| `failed` | 再生が失敗して停止した。再試行できる |

- ファイルを選択しただけでは自動再生しません。
- 再生ボタンまたはSpaceは、再生中なら一時停止、一時停止中なら同じ位置から再開、それ以外は先頭またはシークで準備した位置から再生します。
- 停止は再生位置を先頭へ戻し、選択音源を保持します。
- 自然終了では`finished`へ遷移し、表示時間を音源の長さに合わせて`onNaturalFinish`を通知します。次のエントリの選択はLibraryCoreが担当します。末尾へのシークはこの通知を発行しません。
- 再生失敗では再生を停止し、理由を表示します。選択音源は保持して再試行を受け付けます。
- 音声出力の設定変更通知では停止し、利用者の再生操作で先頭から再開します。

ライブラリからブックマークを解決して得た`FileLease`は、`select(using:)`で読み込み確認へ、`togglePlayPause(using:)`で再生開始へ渡す。再生側が単独で所有し、通常のライブラリ選択では重複保持しない。自動調整ONでは、前処理が確定した測定profileへ`ProfileDecoder`で変換し、そのFloat32 PCMをSFBへ渡す。再生開始・再開時は音源fingerprintと出力profileを再照合し、計画なしの再生を拒否する。背景測定と先行読み込みでは、処理中の同じleaseを共有し、取消後のI/O完了時に解放する。URL・duration・シーク位置を持つ軽量バックエンドは残し、表示・再再生・準備済みシークを維持する。

UIに渡す状態とイベントはmain actorで処理します。SFBAudioEngineのdelegateからは、デコーダオブジェクトを渡さず、終了・失敗・出力変更のイベントを受け渡します。

再生開始ごとにプレイヤーを生成し、デコーダは準備済みのものを一度だけ引き継ぐか新たに生成します。停止時にその再生世代を無効化します。選択・停止・シーク・再再生をまたいだ古い通知が、新しい状態を上書きしないようにします。プレイヤーへ渡したデコーダの所有権は再生ライブラリへ移し、アプリから変更しません。

### シーク

`PlaybackBackend`は`supportsSeeking`と`seek(to:)`を提供する。音源の長さが有効で、デコーダがシークを支持し、再生失敗状態でないときに操作を受け付ける。非有限値は無視し、範囲外は先頭または末尾へ制限する。

| 操作時の状態 | 確定時の動作 |
| --- | --- |
| `ready`／`stopped` | 位置を準備する。自動再生しない |
| `playing` | 確定位置から新しい再生世代を開始する |
| `paused` | 位置を準備し、一時停止を維持する。再開時にその位置から開始する |
| `finished` | 末尾より前へ移動したら`stopped`となり、位置を準備する |
| `empty`／`failed`／シーク非対応 | シークを無効とする |

末尾へ確定した場合は再生を終了し、`finished`と音源長の表示に揃える。停止・出力変更・再生失敗では準備位置も先頭へ戻す。シーク失敗は再生失敗と同じ回復可能な停止とする。

再生中のシークはデコーダを新しく開き、所有権を移す前にPCMフレームへシークしてからSFBAudioEngineへ渡す。一時停止・未再生では位置だけ保持し、再開時に同じ処理を行う。所有権移譲済みデコーダを操作せず、古い終了通知や失敗通知を世代IDで無視する。シークによる再生成で短い再生の切れ目が生じ得るため、連続したスクラブ再生は提供しない。圧縮形式の位置精度はデコーダのフレーム解像度に従う。

## 4. 音量と音声出力

音声はmacOSの既定出力先へ送ります。アプリ内音量はmain mixerの`outputVolume`で0〜1に調整します。初期値は0.25です。非有限値は受け付けず、範囲外の値は0〜1へ制限します。

ミュート中は再生音量を0とし、解除時はミュート前の値を復元する。スライダーを変更するとミュートを解除する。音源選択は音量とミュート状態を維持する。

手動音量はPlaybackCoreの責務である。PlayerUIが操作を受け、`PlaybackController.setVolume`／`toggleMute`が値と状態を管理し、SFBAudioBackendが`mainMixerNode.outputVolume`へ反映する。音量・ミュート変更は再生を継続して行う。

[後処理の追加設計](./audio-processing-design.md)では、EQ・レベル自動調整・同期用ディレイを直列に置き、その後のmainMixerで手動音量を適用する。自動補正と手動音量は別の倍率として管理する。手動音量を全曲測定や補正計画の入力に含めず、その変更で再測定・自動ゲイン再計算を行わない。EQ・ディレイの処理段は将来の追加対象であり、現行実装と区別する。

OSのシステム音量やデバイスのサンプルレートを変更するAPIは使用しません。単曲再生の音量値はアプリの実行中に保持し、永続化しません。製品のデバイス別音量仕様は[基本設計](./basic-design.md)に記載します。

## 5. M4Aの読み込み互換処理

`AudioDecoderFactory`はSFBAudioEngineのデコーダ生成とopenを使用します。M4Aの読み込みが、下位の`NSOSStatusErrorDomain`のeofErr（-39）で失敗した場合に限り、AVAudioFileでPCMを読み取る`PCMDecoding`アダプターへ切り替えます。

アダプターは元音源がAAC／ALACであることを確認します。それ以外の形式や読み込み失敗を正常扱いしません。PCMの再生は引き続きSFBAudioEngineが担当します。依存ライブラリのソースは変更せず、互換処理をアプリ側のデコーダ生成に集約します。

## 6. エラーの扱い

| エラー | 表示・制御 |
| --- | --- |
| `unsupportedFormat` | 対応形式を案内し、不正な再生要求を送らない |
| `inaccessibleFile` | ファイルの場所とアクセス権の確認を案内する |
| `loadingFailed` | 読み込みの失敗理由を表示する |
| `playbackFailed` | 再生を停止し、理由と再試行可能な状態を示す |

選択段階のエラーでは既存の再生を維持します。再生段階のエラーでは、同期・非同期のどちらも再生制御へ通知して停止します。

## 7. 検証方法

### 自動検証

```sh
./scripts/swift.sh test
LCMP_TEST_AUDIO_OUTPUT=1 ./scripts/swift.sh test
python3 scripts/build-app.py
```

通常のテストは音声を出力しません。出力テストは既定出力先へ小さい正弦波を送ります。検証対象は状態遷移、失敗・取消、遅延通知、アクセス解放、元ファイル不変、対応形式のデコード・再生終了、一時停止・再開・停止・再再生、シーク、ミュート復元です。システム音量の比較はデバイスから読み取れる場合に行い、比較の可否をログへ出力します。

テスト音源は独自の正弦波です。開発ビルド後に`python3 scripts/generate-fixtures.py Tests/PlaybackCoreTests/Fixtures`で再生成できます。手動確認用の音源は`python3 scripts/generate-fixtures.py build/manual-audio --duration 12`で生成します。

### 操作と出力の確認

1. `python3 scripts/build-app.py`でアプリを作成し、`open build/LCMP.app`で起動する。
2. 音源領域またはCommand＋Oから対応音源を登録し、リストの「曲を追加」で追加する。曲行を選んで読み込み待ちを確認する。
3. 再生、Spaceによる一時停止・再開、停止、自然終了後の再再生を試し、音声と再生位置を確認する。
4. 再生中に選択画面をキャンセルし、現在の再生が維持されることを確認する。
5. `broken.wav`を登録してリストへ追加し、再生中にその行を選んで、失敗理由と元の再生が維持されることを確認する。
6. 別の有効な曲行を選び、元の再生が停止し、新しい音源が再生待ちになることを確認する。
7. 音量操作がアプリ内音量にのみ作用することを確認する。複数の出力先では切替・切断時の停止・通知・再試行も確認する。

自動テストの再生終了とは別に、実際の可聴性・音質を聴感で確認します。
