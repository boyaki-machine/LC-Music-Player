# コンパクト画面の実装設計

[設計書一覧](./README.md)に戻る。製品の画面方針は[UI・UX設計](./ui-ux-design.md)、再生制御は[基本再生の実装設計](./playback-implementation.md)を参照する。

## 構成

現在の実装名は`LCMP_default_GEQ`とし、画面・操作・可視化を`Sources/PlayerUI/Players/LCMP_default_GEQ/`の1つのフォルダ配下へまとめる。可視化は内部の`Visualization/`に置く。`PlayerUI/PlayerView.swift`はアプリ向けの入口として実装Viewを呼び出す。テストは`Tests/PlayerUITests/Players/LCMP_default_GEQ/`へまとめる。全体の配置と追加規約は[Player UI・可視化の開発ガイド](./playerUI_developers.md)を参照する。

| 要素 | 責務 |
| --- | --- |
| `LCMPApp/AppDelegate` | AppKitのアプリメニュー、ウィンドウの生成・開閉・配置、NSOpenPanel |
| `PlayerUI/PlayerView` | アプリ向け入口。`LCMPDefaultGEQPlayerView`へ依存を渡す |
| `LCMPDefaultGEQPlayerView` | 360×210ptのメイン、144ptの表示領域、6つの44pt操作、シークと音量 |
| `PlayerPresentation` | シーク・音量・拡張の表示状態、拡張画面の選択領域 |
| `ExtensionView` | 現在リスト、音源、表示、設定と詳細エラーの表示 |
| `LibraryControls` | 共通グラス、薄い塗りのボタン、細いスクローラー、現在曲の初期表示、拡張の高さ変更と追加済み表示 |
| `NativeControls` | 背景マテリアル、表示領域の移動操作、キーボードと支援技術に対応したスライダー |
| `WindowLayout` | 画面の可視領域内にメインと直下の拡張を配置する計算 |
| `Visualization/PlaybackVisualization` | 実解析の時刻・世代・再生状態とVisualizationKitの接続 |

メインはタイトルバーのない透明なAppKitウィンドウで、SwiftUIをNSHostingViewに載せる。メインと拡張の角丸は12pt。操作背景は暗いNSVisualEffectViewと半透明チャコールを重ねる。透明度を下げるアクセシビリティ環境では背景マテリアルを隠し、チャコールを不透明にする。

三角は常設し、再生中は緑PLAY、一時停止中は琥珀PAUSE、それ以外は消灯に近いSTOPを表示する。操作名は再生／一時停止／再開へ追従する。短い入力反応は220msで消灯する。音量とメニューは開いている間点灯する。利用できない前後曲は無効で、発光・曲変更を行わない。

現在リストと音源管理は`LibraryController`へ接続し、前後曲・順次再生・複数リストの編集を扱う。拡張の詳細は[ライブラリ・プレイリストの実装設計](./library-implementation.md)を参照する。表示領域は実解析を16列の蛍光管LEDへ渡す。表示タブは現在のデザインを説明し、単一候補の選択UIを置かない。時刻・残光・欠落・寿命は[可視化の実装設計](./visualization-implementation.md)に記載する。

## ウィンドウ操作

- 拡張は幅360pt、初期高さ300pt、間隔2ptでメイン直下へ配置する。開くたび現在リストへ戻り、入力フォーカスを拡張へ移す。閉じても再生・音源・音量は維持する。
- メインの現在画面の`visibleFrame`を使い、Dock・メニューバーを避ける。直下の空間が不足するときは、メインを必要な範囲で上へ移す。上下合わせて収まらない画面では、メインを上端へ配置して拡張を縮め、内容をスクロールする。
- 下端の10ptの操作領域に24×2ptのつまみを描く。`ExtensionResizeHandle`が開始時の高さとスクリーン座標から要求高さを算出し、AppDelegateが`WindowLayout.resizedExtensionHeight`で通常240pt以上・画面下端までへ制限する。メインと拡張の上端・幅を動かさず、一覧領域を伸縮する。つまみにフォーカスがあるときは上キーで20pt縮小、下キーで20pt拡大でき、支援技術の増減にも対応する。
- 希望高さはアプリ実行中に保持し、開閉・最小化・復元でも使用する。画面変更で収まらないときは一時的に縮め、小さな画面では240pt未満も許容する。アプリ終了後の高さ保存は行わない。
- メインの移動と画面構成の変更時に再配置する。通常の拡張開閉では、十分な空間があるメインを動かさない。
- 表示領域の移動はグローバルなポインター座標を基準とし、6pt以上でドラッグと判定する。ドラッグ後の解放ではシーク表示を切り替えない。シーク・音量・ボタンはこの移動領域へイベントを渡さない。
- Command＋Wでメインを閉じても再生を維持する。Dockまたはウィンドウメニューから再表示できる。拡張がアクティブでもCommand＋Wはメインを閉じる。Command＋Mでメインと付随画面を最小化し、復元時は拡張の表示状態を維持する。Command＋Qは再生を終了してアクセスを解放する。

## シークと音量

シークは表示領域の下端に透明な背景で重ね、ウィンドウを大きくしない。NSSliderの追跡・入力機能に2ptのバーと8ptのつまみを描くセルを組み合わせ、時間表示を添え、操作領域は高さ24ptとする。再生位置は200msごとに現在バックエンドから読み、別の音源の位置通知を保存しない。

PlayerPresentationは2秒の取消可能な非表示タイマーを持つ。シーク領域へのホバー、スライダーの入力フォーカス取得・操作で取り消し、退出・フォーカス喪失・領域外クリック・メインのキー喪失・アプリ非アクティブ化で再設定する。シーク表示時は入力フォーカスを強制せず、キーボードではTabでスライダーへ移動できる。閉じる・最小化・終了時にはタイマーも取り消す。

マウス操作中はUIだけに位置をプレビューし、解放時に確定する。音源・再生状態が変わった場合、表示を閉じた場合、Escapeではプレビューを破棄する。確定対象のURLが変わっていたらシークを送らない。左右キーと支援技術による変更は、その入力で確定する。再生状態ごとの処理は基本再生の実装設計に記載する。

音量ポップアップは54×132ptで表示領域内に収める。縦スライダーは上が増加、下が減少。上下キーは5ポイントずつ変更する。開いた際はスライダーへ入力フォーカスを移す。ポップアップと音量ボタンの外のマウス押下はローカルイベントモニターで観測して閉じ、イベントはクリック先へそのまま渡す。音量ボタンは自身の開閉処理へ渡し、外部クリック処理による再オープンを防ぐ。ポップアップの破棄時にモニターを解除し、アプリ非アクティブ時にも音量表示を閉じる。ミュートを解除すると直前のアプリ内音量へ戻り、スライダーを変更した場合はミュートを解除する。音源の差し替えでも現在音量とミュートを維持する。

## キーボードと支援技術

| 入力 | 操作 |
| --- | --- |
| Command＋O | 音源登録 |
| Command＋I | M3U8読み込み |
| Space | 再生／一時停止／再開 |
| Command＋ピリオド | 停止 |
| Command＋S | シーク表示切替 |
| Command＋U | 音量表示切替 |
| Command＋E | 拡張表示切替 |
| Command＋0 | メインを表示 |
| Command＋M／W／Q | 最小化／閉じる／終了 |
| スライダーの矢印キー | 位置・音量の変更 |
| スライダー上のEscape | ポップアップとシーク表示を閉じる |

各ボタンに操作名、三角に再生状態、スライダーに名称と現在値を公開する。支援技術からの値設定と増減も、通常操作と同じ変更・確定処理へ送る。メインのエラー表示から拡張の音源領域へ進み、理由の確認と再選択を行える。メインにファイル名は常設しない。

## 検証手順

1. 通常のテストで画面端・負の座標の配置、拡張再表示、再生状態・シーク・ミュートの境界を確認する。
2. `LCMP_UI_SNAPSHOTS="$PWD/build/ui-qa" ./scripts/swift.sh test --filter NativeViewTests`でメインとポップアップのネイティブ描画を生成する。
3. アプリでファイル選択と取消、再生状態とLED、メニューの再表示、ドラッグとクリックの区別を確認する。
4. マウス、矢印キー、支援技術でシークと音量を変更し、表示値、音声、ウィンドウ位置を確認する。ミュートとEscape、閉じる・最小化・復元を試す。
5. 下端を上下へドラッグし、幅・上端・メイン位置が固定されること、画面下端と最小高さで止まること、閉じて開き直しても高さを維持することを確認する。つまみの上下キーと支援技術の増減も確認する。
6. 複数画面と画面端で付随位置を確認し、macOSの透明度を下げる設定で文字と操作の視認性を確認する。

## 再生前処理への接続

Player UIは再生の開始・前後曲・停止をLibraryControllerへ渡し、停止は準備中にも有効にする。拡張画面は`isPreparing`を表示する。設定タブはScrollView内に最大音量測定のToggle、説明、測定状態・dBFSまたは無音を表示し、`setMeasuresMaximumVolume(_:)`で変更する。最小240ptでも説明を折り返し、残りはスクロールで読める構成にする。デコード・測定・キャッシュはViewが所有しない。仕様は[再生前処理](./preprocessing-implementation.md)を参照する。
