# 音量自動調整と前処理拡張の設計

[設計書一覧](./README.md)に戻る。

本書は、全曲のラウドネスとピークを併用する音量自動調整の仕様と実装を記述する。前処理による測定と、再生経路での固定ゲイン適用を分離する。LUFS/true peak測定と固定ゲイン、再生待ち・設定は実装対象である。EQと同期用ディレイは将来の処理段として構成を定義し、現行の実装と区別する。[前処理](./preprocessing-implementation.md)のnative先頭PCMとsample peak専用APIも維持する。

## 1. 目的と調整方針

- 曲全体のIntegrated Loudness（LUFS）を用いて、曲間の聴感上の音量差を減らす。
- true peakによって増幅の余裕を判断し、ピークの制約を音量目標より優先する。
- 1曲を通じて同じ倍率を全チャンネルへ適用し、曲内の強弱と左右バランスを保つ。
- 手動音量とミュートを自動補正から分離し、OSのシステム音量を操作しない。
- 測定は背景処理で行い、再生render callbackへ全曲解析・I/Oを追加しない。

ピーク制約や増幅上限によって、目標LUFSに達しない曲がある。目標達成のためにピークをつぶすコンプレッサーやリミッターは、この固定ゲイン方式に含めない。アルバム内の曲間差を保つアルバム単位補正、周波数EQ、同期用の音声ディレイも別の機能とする。

LUFSは聴感に近い指標であり、あらゆる曲・聴取環境の音量感を完全に一致させる保証ではない。dBTPの上限は測定したデジタル音声に対する予測であり、ヘッドフォン等からの物理音圧の上限ではない。

## 2. 責務とデータの流れ

次は、EQと同期用ディレイを無効にし、レベル自動調整を使う場合の構成である。

```text
LibraryCore（再生要求、参照、設定、測定待ち、取消）
    ↓
PreprocessingCore
    ├─ native先頭PCMと再生用デコーダの準備
    └─ 独立デコーダ → 共通の形式変換 → 出力形式に合わせたPCM
                         ├─ sample peak / true peak
                         └─ K-weighting → 全曲LUFS
    ↓ TrackAudioMetrics（完了値＋音源/測定条件の識別情報）
AudioProcessingCore（設定検証 → NormalizationPlan）
    ↓
PlaybackCore / SFBAudioBackend
    ProfileDecoder → source → mixer → 観測ノード → 自動補正gain → mainMixer → OS出力
                              ↓                         手動音量/mute
                         AnalysisCore → 可視化
```

`AudioProcessingCore`は数値設定・測定器・補正量の計算・専用gainノードを持つ。Foundation、AVFAudioと独立したCターゲット`LevelDSP`を使用し、SFBAudioEngine、PreprocessingCore、LibraryCore、UIへ依存させない。`LevelDSP`はworker上でK-weightingと補間を行い、数値ループを最適化してビルドする。PreprocessingCoreはこのDSPをチャンク入力で利用し、ファイル・デコーダ・測定資源の寿命を管理する。PlaybackCoreとLibraryCoreもAudioProcessingCoreの値型を利用する。UIからAudio Unitを直接操作しない。

既存の観測用0band EQはglobalGain=0のままとし、補正専用の0band `AVAudioUnitEQ`をその後へ置く。解析購読の有無・最小化・ウィンドウ非表示で補正を解除しない。可視化の値は自動補正・手動音量より前の音源レベルを表し、出力レベル計として扱わない。

SFBAudioEngineのグラフ変更はsourceとmainMixerの間だけで行う。sourceの初期形式や内部ring bufferをアプリ側から先に変更せず、SFBへデコーダ形式の設定を委ねる。エンジンの開始・停止はプレイヤーのAPIを使う。

### 処理段の重ね合わせと順序

音声処理部（後処理部）は、フィルターのように複数の機能を順に通す処理列とする。各段を独立して有効・無効にでき、EQだけ、レベル調整だけ、両方とディレイの併用を可能にする。ここでの多重適用は、前段の出力を次段の入力へ渡す直列処理を意味する。

将来のEQと同期用ディレイを含む順序は、次で固定する。利用者による順序の並べ替えは提供する要件に含めない。

```text
形式変換後のPCM
    ├─ 観測 → 周波数解析・可視化
    └─ EQ → レベル自動調整 → 同期用ディレイ → 手動音量・ミュート → 出力
```

| 処理段 | 役割 | 無効時 |
| --- | --- | --- |
| EQ | 周波数ごとの特性を調整する | 波形をそのまま次段へ渡す |
| レベル自動調整 | EQ適用後の全曲LUFS/true peakを基準に固定ゲインを適用する | gain=0dBで通す |
| 同期用ディレイ | 音声と可視化の同期のために提示時刻を遅らせる。振幅・周波数特性は変えない | 追加遅延0で通す |

各段は自身の設定だけを適用し、他段を暗黙に無効化しない。すべて無効なら、後処理部は波形と提示時刻を意図的に変更せず、手動音量段へ渡す。パススルーは後処理部の加工に関する契約であり、手動音量・ミュートやデコード・出力形式変換も無効になる意味ではない。

EQを先に置くことで、その増幅・減衰を含む音声に対してレベル調整を決定する。EQが有効なときは測定側でも同じ設定のEQを通し、設定と実装版をMeasurementProfileへ含める。EQのON/OFF・設定変更では以前の測定結果と補正計画を失効させ、レベル調整ONなら再測定してから再生する。EQの音声側と測定側は別のインスタンスとし、フィルター状態を共有しない。

同期用ディレイは波形の振幅を変えない時間移動なので、その遅延量だけの変更では全曲LUFS/true peakを取り直さない。提示時刻・解析世代・末尾排出と再生位置の扱いは、[同期補償の契約](./analysis-implementation.md)に従って更新する。上の処理順序は追加機能の構成を定めるもので、EQやディレイが現在実装済みであることは意味しない。

### 手動音量とミュートの担当

手動音量とミュートは、PlaybackCoreによる再生・出力制御の責務とし、後処理列の後に適用する。

| 担当 | 責務 |
| --- | --- |
| PlayerUI | 音量スライダー・ミュート操作を受け付け、PlaybackControllerへ渡す |
| PlaybackController | `setVolume`／`toggleMute`で音量値、ミュート状態、解除時に戻す値を管理する |
| SFBAudioBackend | 最終段の`mainMixerNode.outputVolume`へ音量を適用する |
| AudioProcessingCore | 曲ごとの補正計画と加工段を担当し、手動音量値を所有・上書きしない |

自動補正は曲ごとの差を補う倍率、手動音量は利用者が聴く大きさを決める最終倍率である。全体の振幅には両方の倍率がかかる。手動音量は0〜1の範囲で、1は自動補正後の振幅を維持し、0は無音にする。ミュートはこの最終倍率を0にする。

手動音量やミュートは測定profileと補正計画の入力に含めず、変更しても全曲再測定・自動ゲイン再計算を行わない。手動音量の変更のたびに再生を一時停止しない。自動調整のON/OFFやEQ設定変更による再準備とは異なる操作として扱う。自動調整のON/OFF・曲切替でも手動音量とミュート状態を維持し、OSのシステム音量を変更しない。

## 3. 測定結果と再利用の単位

| 型 | 主な内容 |
| --- | --- |
| `MeasurementProfile` | 出力レート、チャンネル配置、mono/stereo変換、変換品質・アルゴリズム版、測定DSP版。前段EQの有効状態・設定・実装版はEQ追加時の拡張 |
| `AudioLevelMetrics` | Integrated LUFSまたは測定不能理由、sample peak、true peak、フレーム数、gating block数 |
| `TrackAudioMetrics` | SourceFingerprint、MeasurementProfile、AudioLevelMetrics、測定完了の識別情報 |
| `NormalizationSettings` | 目標LUFS、true-peak上限、測定誤差用の余裕、増幅上限。有効状態はLibraryControllerが管理 |
| `NormalizationPlan` | 測定profile、設定のsnapshot、適用gain dB・線形倍率、制約理由。音源の照合情報はSFBAudioBackendがTrackAudioMetricsとして保持 |

`integratedLUFS`は、有限の測定値と、無音・gating対象なし・短すぎる音源を区別する。JSONやUIへNaN/Infinityを数値として保存・表示しない。ピークの線形0は無音として扱う。非有限の入力サンプルは無音へ置換せず測定失敗とする。

既存の`TrackPeak`・`measure`・`currentTrackPeak`はsample peak専用の互換APIとして残す。`TrackPeak`をLUFS/true peak付きの結果と見なさない。新しい全曲APIを`measureLevels`、公開状態を`levelMeasurement`、有効な完了値を返す入口を`currentTrackMetrics`とする。これらは前処理の公開APIである。

測定値は設定の目標LUFSに依存させない。目標や増幅上限だけが変わった場合は、同じ測定結果から計画を再計算する。音源の識別情報・サイズ・更新日時、レート、チャンネル変換、測定版、前段EQが変わった場合は再測定する。URLだけ、曲IDだけ、古いsample peakだけで再利用しない。属性照合は制御側で行い、render callbackでファイルを調べない。

先頭PCMの対象は現在曲と直後1曲に限定し、全曲測定は全プレイリスト所属曲を一件ずつ巡回する。リストに含まれないライブラリ音源は走査しない。完了測定値は[永続キャッシュ](./measurement-cache-implementation.md)へ保存する。Stopや終了で進行中の測定とメモリ保持を破棄し、同じ有効な計画によるpause/resume・seekは全曲再測定を不要にする。結果の保持にファイルleaseを持たせない。

## 4. 前処理の追加測定

### 測定するPCMの位置

自動補正前・手動音量前の音声を測る。native PCMのsample peakは従来どおり保持できるが、補正計画には、再生時の形式変換後、かつ前段EQ適用後に相当するPCMから求めたLUFSとtrue peakを使う。EQが無効なら同じ位置をパススルーとする。可視化の周波数解析はEQより前を観測し、この補正用測定とは分ける。

monoを同振幅の左右へ複製すると、左右のエネルギー和はmonoと異なる。レート変換もピークを変え得るため、ファイルのnative LUFS/peakだけを出力形式の測定値として扱わない。`ProfileConversion`でAVAudioConverterの設定を共有し、測定と自動調整ONの再生用`ProfileDecoder`に適用する。monoからstereoは両チャンネルへ同振幅で写す。ProfileDecoderはnative先頭PCM付きデコーダを包み、SFBのdecode threadで変換後のPCMを返す。その後のmixerへ同じレート・チャンネル数を渡すことで、暗黙のチャンネル変換への依存を避ける。OFFの再生は従来のnativeデコーダ経路を維持する。profileへ変換版を含め、offline測定PCMと再生側の波形を照合する。

profileは再生準備時に実際の出力形式から作り、scan開始時と再生開始直前に照合する。scan中の出力変更で古いprofileのまま再生を始めない。変換APIの設定名が同じだけでは同一波形と見なさず、照合に通らない変換は対応profileへ登録しない。

対象はmono/stereoの入力とmono/stereoの処理出力、処理出力レート44.1/48/96kHzとする。任意の多ch配置を先頭2chだけで代用しない。未対応の配置や未検証の変換profileは自動調整不可として理由を表示する。自動調整OFFでの既存再生形式の対応を狭めない。

### Integrated Loudness

ITU-R BS.1770-5の測定方式に沿い、チャンネル別K-weightingとエネルギー集約を行う。400msの完全なblockを100ms間隔で評価し、絶対gateと相対gateを適用して全曲値を求める。左右を波形平均して逆相成分を消さない。K-weightingの係数は実際の測定レートへ合わせ、48kHz用の係数を他レートへそのまま流用しない。方式の詳細は[ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I)と[EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf)を基準にする。

二段階gatingのため、最初の走査ではblockごとのチャンネル重み付きエネルギーをFloat64で記録する。曲全体のPCMは保存しない。エネルギー列を再走査して相対gateを適用するため、同じ音源をもう一度全デコードする必要はない。無限に増える配列や精度未検証のヒストグラムで代用しない。

blockエネルギーは小さい固定長バッファで一時ファイルへ逐次保存する。1block 8byte、毎秒10blockなら約0.275MiB/時で、ファイル上限を64MiBとする。上限やI/Oエラーでは失敗とし、途中までのLUFSを全曲値として返さない。一時ファイルはランダム名・所有者のみアクセス可能とし、曲名やパス、音声波形を含めず、正常終了・取消・失敗で削除する。異常終了で残った専用一時ファイルは次回起動時に回収する。他プロセスが使用中のファイルは削除しない。

使用中の一時ファイルはプロセス間の排他ロックで保護し、回収側はそのロックを取得できる残存ファイルだけを削除する。PIDの存在確認だけで使用中判定を代用しない。エネルギー列の再走査も固定長バッファで行い、64MiB全体を配列化しない。

EOFの不完全blockはLUFSへ加えないが、その区間もピーク測定には含める。400ms未満ではゼロ埋めによる架空のIntegrated値を作らず、`tooShort`とする。完全なblockがすべてgateの対象外なら`belowGate`とし、静かなノイズを大幅に持ち上げる根拠にしない。

### ピーク

sample peakは全チャンネルの絶対値最大を求める。true peakはK-weighting前のPCMを補間して求め、チャンネルごとの最大のうち最大を使用する。LUFS計算用のフィルターをtrue-peak経路へ入れない。

true-peak測定はBS.1770の補間方式とレートごとのフィルターを使う。例えば48kHzでは4倍、96kHzでは2倍、44.1kHzでは8倍を基準とし、測定用の内部レートを192kHz以上にする。Cの32tap Blackman窓付きsinc補間を用い、各位相をDC gain=1へ正規化する。倍率だけで適合とせず、補間係数・ゲイン補償・誤差を試験する。チャンク境界でフィルター状態を保持し、先頭・EOFのフィルター応答も評価する。EOFの排出サンプルはtrue peakの確認用で、曲の長さやLUFSのblockへ加えない。出力音声自体をこの高レートへ変更する仕様ではない。

### キューと完了条件

既存のutility直列ワーカーを使い、8192入力フレーム以下の処理ごとに取消を確認する。優先順位は、明示された再生要求、再生中の現在曲と前後（直後優先）、現在リストの残り、他リストの順とする。実行中の低優先度測定はチャンク境界で後へ回し、明示再生を待たせ続けない。

背景の測定は一件ずつ処理し、同じfingerprint/profileの要求は合流する。再生デコーダはscanへ流用しない。1回の測定走査からLUFS・sample peak・true peakを作り、別々の全曲scanを重ねない。既存のsample peak専用要求は、必要なら安い専用経路のまま扱う。

EOF、既知フレーム長との一致、形式変換器と補間器の排出、エネルギー列のgating、fingerprint再照合をすべて終えてからcompleteとする。途中結果や不一致は計画作成に使用しない。

## 5. 補正量の決定

設定値を次のように表す。これらは別々のパラメーターであり、目標LUFSをピーク値で代用しない。

| 記号 | 意味 |
| --- | --- |
| `T` | 目標Integrated LUFS |
| `C` | true-peak上限（dBTP） |
| `M` | 測定誤差等に備える余裕（0以上のdB） |
| `U` | 自動増幅の上限（0以上のdB） |
| `L` / `P` | 測定したLUFS / true peak（dBTP） |

設定値は有限で、`T < 0`、`C <= 0`、`M >= 0`、`0 <= U <= 24`を満たすものだけを受け付ける。増幅の技術的上限24dBはAUの表現範囲であり、推奨値ではない。さらに検証済みの設定profileに含まれることを確認し、未検証の保存値をそのまま適用しない。

```text
ラウドネスから必要な補正 = T − L
ピークから許される補正   = C − M − P
適用補正 G              = min(T − L, C − M − P, U)
線形倍率                 = 10^(G / 20)
```

減衰を0dBへ丸めたり、増幅時だけピーク制約を適用したりしない。減衰下限を設けて必要な補正を妨げない。AUの表現範囲を超える補正や非有限の演算結果は、下限へのclampで正常扱いせず再生準備の失敗とする。

無音はgain=0dBとする。`tooShort`または`belowGate`で有限LUFSが得られない非無音は、増幅せず`min(0, C − M − P)`で必要な減衰だけを行い、「ラウドネス補正対象外」と表示する。ピークまで取得できなかった失敗とは区別する。

計画は`targetReached`、`peakLimited`、`boostLimited`、`noIntegratedLoudness`、`silent`の理由を持つ。増幅とピークの同値制約ではピークを優先して表示する。`L + G`は予測値として扱う。固定された絶対gateの影響等により、再測定結果との完全一致を約束しない。試験では補正後PCMを独立に測定する。

初期profileは目標−23LUFS、true-peak上限−1dBTP、余裕0.5dB、最大増幅+6dBとする。−23/−1は参照可能なEBU R128の基準を開始点として使用し、放送全体の規格準拠を表すものではない。+6dBは過度な持ち上げを避ける製品上の約2倍の増幅制限で、規格由来の値ではない。目標はUIから−23/−18/−16LUFSを選べる。ピーク制約を優先し、目標が高いほど必ず音が大きくなる仕様にはしない。

## 6. 再生準備と操作

| 状況 | 動作 |
| --- | --- |
| 自動調整OFF | gain=0dB。全曲LUFS測定を再生開始条件にしない |
| ON、有効な測定結果あり | 計画を確定し、最初の出力サンプルから同じgainを適用 |
| ON、未測定 | 測定と準備を背景で行い、完了するまで対象曲の出力を開始しない |
| ON、次曲が測定済み | 次曲の計画と先頭デコーダを再照合して引き継ぐ |
| ON、次曲測定が間に合わない | 現在曲の終端後に準備待ち。未補正再生や黙った曲飛ばしをしない |
| 測定/参照/保存の失敗 | 新しい選択を確定せず、旧選択・旧再生を維持。失敗を表示 |
| 準備中のStop/別の再生要求/終了 | 要求世代を無効化し、scan・一時ファイル・デコーダ・leaseを解放 |
| pause/resume・seek | 同じ音源/profile/設定の計画を保つ。seek後も途中区間だけでLUFSを取り直さない |
| 出力形式/チャンネル配置変更 | 既存の出力変更時停止を維持し、古い計画を失効。次の再生要求で再照合/再測定 |

`isPreparing`と`preparationStage`で、先頭準備／全曲測定の短い状態文を拡張画面へ渡す。測定の進捗バー・スピナー・割合・残り時間は表示せず、PCMチャンクごとのMainActor通知も追加しない。補正計画は有効な完了値が揃ってから確定する。

LibraryControllerで再生要求を一元管理し、pausedからのresume、前後曲、自然送り、再再生も同じ検査を通す。PlaybackController側でもONかつ有効な計画がない再生を拒否し、UI経由以外で未調整再生できる抜け道を作らない。準備失敗を「音源が存在しない」と誤って登録しない。

手動の曲切替準備中は旧再生を維持する。新しい音源/測定/profile/計画をそろえ、ライブラリ保存に成功してから差し替える。準備中に旧曲が自然終了しても、別の自然送りで明示要求を上書きしない。保存失敗で旧曲がすでに終わっている場合は、その終了状態を保持する。

設定変更を曲中に段差で適用しない設計とする。再生中のON/OFFや補正値変更では一時停止し、位置を保持する。利用者が再生を押したときに新しい計画を準備して同位置から再開する。準備完了だけで勝手に再開しない。設定版と実際の適用計画を区別し、旧計画のまま「新設定を適用中」と表示しない。

この一時停止は自動補正や加工段の設定変更に適用する。最終段の手動音量・ミュート変更は再生を継続して反映する。

## 7. 設定と画面

利用者向けの主設定は「曲ごとの音量をそろえる」とし、既定OFFで永続化する。既存の`measureMaximumVolume`がONだっただけでは、新しい音声加工を自動的にONにしない。最大音量の測定専用機能は独立して維持できる。

自動調整ONはLUFS/ピーク測定を必須とし、測定専用スイッチがOFFでも測定を行う。両方OFFでもプレイリスト事前測定は有効だが、未測定をOFFの再生開始条件にしない。目標音量の選択はUserDefaultsの`normalizationTargetLUFS`へ保存し、有効状態は`normalizeVolume`へ保存する。不正値は基準profileへ戻す。true-peak上限・余裕・増幅上限は設定型で検証し、最初のUIでは個別の調整欄を並べない。

拡張画面には、測定中、適用中の補正dB、ピーク/増幅上限による制限、補正対象外、失敗と再試行を表示する。設定の変更で一時停止することを操作前に説明する。LUFS/dBTP/dBFSを混同した「最大音量」の1値にまとめず、詳細で単位を示す。メイン画面に曲名や測定値を常設せず、240ptの拡張でも折り返し・スクロールで読める構成にする。

## 8. 資源・音質・遅延の契約

再生用のnative先頭PCM上限2秒/32MiBは維持する。追加測定は8192入力フレーム以下のPCM、形式変換/補間の固定作業領域、400ms窓を構成する固定長状態、blockエネルギーの小さいI/Oバッファを持つ。曲長に比例してPCMや測定履歴をメモリへ蓄積しない。

通常は現在曲のアクセス1つと次曲準備/巡回が共有する先行アクセス1つを上限とし、該当曲のscanは同じleaseを共有する。自動調整ONで同じエントリ・音源参照へ切り替える場合は、未完了の次曲Taskとleaseを選択要求へ移す。異なる要求では投機処理を取り消し、その終了を確認して候補へ枠を渡す。decoder.openの取消不能区間を含めて無制限に新しい処理を積まない。Stop・終了後は非同期I/Oの片付け完了時にアクセス0とする。

gainは曲開始前に確定し、再生中は固定する。測定器のK-weightingや補間を音声出力経路へ挿入しない。固定gain段に意図的な音声FIFOやlook-aheadを加えず、曲末に独自の遅延音声を残さない。追加DSP遅延はインパルスで測定し、未測定の「0遅延」を保証しない。全曲測定による開始待ちとは別の値として評価する。

true peakはprofileに対する推定である。再サンプリングやseek直後の変換状態、OS/機器での後段処理は別途誤差を生み得る。余裕`M`を設け、再生経路との照合が通らないprofileは有効にしない。未知の出力経路でも絶対的なtrue-peak上限を保証するには、最終経路の検証や別のリミッター設計が必要になる。

## 9. 検証契約

1. 独自生成の信号でK-weighting、絶対/相対gate、mono/stereo/逆相、無音、非有限値、EOF端数と400ms未満を確認する。合成可能なEBU Tech 3341の測定試験は各項目の許容差で照合し、LUFSの基本信号は±0.1LUを基準にする。全EBU機能を実装していない段階でEBU Mode準拠を名乗らない。
2. 既知のサンプル間ピーク、先頭/末尾インパルス、チャンク境界、44.1/48/96kHzと24bit入力を検証する。true-peak試験は基準信号ごとの許容差を使い、内部倍率だけで合格としない。
3. 固定ゲインの計算は独立した期待値と比較し、ピーク制約を必要減衰がある場合にも守る。quiet/tooShort/belowGateで不要な増幅がないことを確認する。適用後PCMを独立メーターで測り、予測値・余裕・誤差を区別する。
4. 測定adapterと再生の変換後PCMのLUFS差・true-peak差をレート変換あり/なし、mono/stereo、seek境界で比較する。メーター誤差と変換誤差の合計が設定の余裕を超えるprofileは不合格とする。下流のハードウェア音圧はこの判定に含めない。
5. 指標の一時ファイル上限/取消/失敗/異常終了後回収、長い入力のメモリ上限、同一要求の合流、明示再生の優先を確認する。完了前やfingerprint/profile不一致を再生へ渡さない。
6. 設定の移行、pause/resume/seek、曲切替/自然送り/Stop/終了、参照修復/保存失敗、古い結果、音量/mute、解析の購読解除/非表示を回帰する。再生出力は補正の有無を反映し、可視化は同じpre-gain値を維持する。
7. OFFとONの波形誤差、追加DSP遅延、開始待ち、全曲測定の速度、CPU/RSS、PCM dropと資源解放を比較する。10分の固定補正再生と全曲scanを伴う条件を分け、既存の実出力全回帰は`--no-parallel`で行う。実施結果は開発記録へ残す。
8. EQ・同期用ディレイの導入時は、各段の単独・全段併用・各段バイパスの組合せで順序と出力を確認する。EQ設定変更で測定/計画が失効し、手動音量・ミュート・時間移動だけの変更では再測定されないことを検証する。自動補正と手動音量の倍率の積、ミュート解除、自動補正OFFでも手動音量が保たれることを確認する。純粋なディレイの振幅保存、解析時刻、末尾排出の試験も追加する。

## 実装上の公開入口

- `AudioPreprocessor.measureLevels`：utilityキューで全曲測定。native sample peakも同じ走査で求め、測定専用スイッチがONの場合の二重scanを避ける。
- `ProfileDecoder`：元のデコーダから共有規則で変換したPCMを返す。8192フレームの固定作業バッファと残量を持ち、部分読みでも要求バッファを満たし、EOFだけを短い読み取りにする。seekは入力側の時刻へ換算し変換器をresetする。
- `LibraryController.setNormalizesVolume`／`setNormalizationTarget`：設定、現在/次曲の測定結果、再生準備を管理。`levelMeasurement`／`currentTrackMetrics`／`preparationStage`を表示へ渡す。
- `PlaybackController.requireNormalization`：有効時に計画なしの再生・resumeを拒否。設定変更はpauseし、OFFでは旧gainを解除する。
- `selectPrepared(...metrics:settings:)`：音源と測定結果を照合し、保存成功後に現在の再生を差し替える。
- `SFBAudioBackend`：開始・再開時にfingerprintと実際の出力profileを再照合し、ProfileDecoderと独立gainノードを所有する。`AudioProcessingChain`はレベル段を持ち、EQ/delayの追加位置をその前/後に定める。

### 負荷比較の実行方法

独自生成の長さ60秒以上の`tone.wav`と`tone.flac`を検証専用ディレクトリへ置く。利用者のライブラリへ登録せず、テスト用の参照・設定だけを使う。

```sh
LCMP_NORMALIZATION_PROFILE=1 LCMP_NORMALIZATION_SOAK=1 \
LCMP_PREPROCESS_FIXTURES=<検証用ディレクトリの絶対パス> \
  ./scripts/swift.sh test --disable-automatic-resolution --no-parallel \
  --filter PreprocessingPerformanceTests
```

`normalization-profile.json`にON/OFFのsteady区間CPU/RSSと開始待ち、`normalization-soak.json`に600秒の補正/全曲測定/FFTと反復切替のCPU・RSS・PCM drop・最大lease・停止後解放を記録する。アプリ音量は0で、物理的な出音/画面提示の検証とは区別する。実行中のtest bundleを別のSwift build/testで上書きしない。
